# 配音工作台工具设计方案 v0.1

- 项目：Dubbing workbench（配音工作台）
- 日期：2026-09-24
- 状态：首版设计草案，作为产品讨论与开发拆分依据；不代表功能已经实现或模型效果已经验收。
- 目标：将小说逐章制作成多角色有声书，支持角色音色延续、剧本校对、逐条返工与章节导出。

## 1. 产品定位

配音工作台面向需要持续制作小说有声书的创作者。用户上传章节，AI 提取旁白、对白和心理独白，用户确认角色与音色后生成音频，再通过对照剧本试听、修改和单条重跑完成章节制作。

产品核心是让用户能够掌控每一条配音，并在多章制作中保持角色一致。AI 负责建议与生成，用户决定角色归属、音色选择、表演要求和最终导出。

### 1.1 核心价值

1. 降低小说整理为配音剧本的成本。
2. 用项目角色档案延续跨章节的角色身份与默认音色。
3. 修改不满意的片段时，只重做受影响的部分。
4. 让连续试听与最终导出的顺序、停顿和音量处理保持一致。
5. 保存制作进度，避免刷新页面或部分生成失败导致整章重来。

## 2. 第一版范围

### 2.1 纳入第一版

| 模块 | 第一版能力 |
| --- | --- |
| 项目与章节 | 创建、重命名项目；导入、排序、打开章节；保存制作进度 |
| 文本导入 | UTF-8 TXT、Markdown、直接粘贴文本；一次处理一个章节 |
| 剧本提取 | 区分旁白、角色对白、心理独白；建议说话人和情绪；标记待确认项 |
| 剧本校对 | 查看原文；纠正角色、文字、音色、表演要求；拆分及合并相邻片段 |
| 项目角色 | 姓名、别名、简介、性别信息、默认音色；跨章节复用 |
| 音色库 | 上传参考音频、命名、试听、生成测试样音、保存为可复用音色档案 |
| 配音生成 | 当前章节批量生成、进度展示、失败定位、单条重跑、补做失败或待更新项 |
| 试听检查 | 单条试听、全章顺序播放、暂停、定位、当前条高亮、跟随滚动 |
| 章节导出 | 按当前音频与间隔设置合并，下载 WAV 或 MP3 |
| 设置 | 片段间隔、模型服务配置；服务凭据仅在服务端保存 |

### 2.2 暂不纳入第一版

- 整本小说无人值守批量制作、多人实时协作。
- 背景音乐、环境音、复杂音效编排和多轨时间轴。
- 自动改写小说、自动删改叙述内容。
- EPUB、PDF、扫描件识别与复杂排版解析。
- 字级字幕、自动口型同步、视频配音对齐。
- 自行训练语音模型或承诺上传后得到永久供应商音色 ID。
- 自动发布到有声书平台。

第一版以中文小说为主要验收对象；其他语言不默认视为已经支持。

## 3. 核心概念

| 概念 | 定义 |
| --- | --- |
| 项目 | 一本小说或一个独立制作任务，包含章节及其共享角色档案 |
| 章节 | 一次可独立生成、检查和导出的制作单元 |
| 角色 | 项目内稳定身份，包含别名、简介与默认音色；旁白作为特殊角色管理 |
| 音色档案 | 用户命名的参考声音资产，第一版主要由保存的参考音频构成 |
| 配音片段 | 剧本列表中的一条，也是独立生成、试听和返工的最小单元 |
| 当前音频 | 当前用于连续试听与导出的片段音频 |
| 待更新音频 | 设置已修改、当前音频尚未按最新设置重新生成的状态 |

“每一句”在产品中表现为一条配音片段，不机械地等同于一个句号。短对白通常独立一条，同一说话人、相近情绪的连续旁白可以保留为短段落。长片段按语义边界拆分。

## 4. 完整制作流程

1. 创建或打开项目。
2. 上传或粘贴章节，确认章节标题和正文。
3. AI 结合本章原文、已有角色档案及必要上下文提取剧本。
4. 用户检查待确认角色、别名匹配、说话人归属与文本分段。
5. 展示本章角色列表，为未配置音色的角色选择音色。
6. 用户检查剧本中的音色和表演要求。
7. 开始整章配音，展示逐条状态与总进度。
8. 对照剧本连续试听，修改不满意的条目并重跑。
9. 确认所有条目都有与当前设置一致的可用音频。
10. 点击“合并并导出”，生成章节文件并下载。

角色列表与剧本可以随时查看。生成、单条重跑和合并期间，本章内容只读，避免生成内容与界面设置不一致；其他章节不因此被全局锁定。

## 5. 小说转剧本

### 5.1 提取原则

- 默认保留小说朗读正文，不润色、不扩写、不漏句、不重复。
- 标点、Markdown 标记等必要清理应可在原文对照中检查；不自动删去“他说”等叙述。
- 区分旁白、对白、心理独白；心理独白关联原角色，不另建同名角色。
- 角色身份或性别缺乏依据时显示“待确认”或“未知”，不把猜测当作事实。
- 简介只使用截至当前章节已知的原文信息，避免提前引入后续情节。
- 提取结果可修改，AI 不覆盖已经确认的角色绑定与手工校对。

### 5.2 上下文与角色匹配

优先在可用上下文范围内分析完整章节。需要分段时，携带相邻文本和项目角色档案，重叠部分仅用于理解，不重复输出。

前后几句话可帮助判断隐式对话，但不能作为准确率保证。连续无署名对话、代词指代、首次出现的人物和别名匹配，应在无法确定时进入“待确认”列表。

项目角色档案使用普通持久化记录实现，不为第一版引入额外的长期记忆系统。AI 提议将新称呼归入已有角色，用户确认后才写入正式别名。

### 5.3 校对能力

- 展开一条片段对应的原文及前后文。
- 修改角色归属、台词、类型、音色和表演要求。
- 拆分过长片段；合并同角色、同类型的相邻片段，并重新确认表演设置。
- 区分“原文”和“当前朗读文本”，保留用户纠正记录所需的信息。
- 已有音频的片段发生变化时保留旧音频，并标记“待重新生成”。
- 拆分、合并后产生的新片段需要重新生成，不将旧音频错误地分配给新片段。
- 重新提取章节时先展示新草稿，明确用户采用后才替换已编辑剧本。

## 6. 角色与音色库

### 6.1 项目角色档案

每个角色保存：稳定 ID、显示名称、别名、简介、性别信息及其确认状态、默认音色关联。旁白同样需要配置音色。

每次开始整章生成前，展示本章实际出现的角色、简介、音色和待确认项。角色无音色、片段无有效说话人等问题需要解决后才可批量生成。

### 6.2 音色档案建立流程

1. 上传参考音频。
2. 检查格式、文件大小、可解码性和时长。
3. 命名并填写可选描述，试听参考声音。
4. 用户主动点击“生成测试样音”，使用新文本检查参考声音的复用效果。
5. 保存音色档案；样音是否已检查应明确显示。

音色库独立于具体项目，同一用户可在不同项目复用。所有角色音色及单条覆盖均必须选自音色库。

第一版优先支持 WAV、MP3 上传。按现有核验文档，一条参考音频最长 30 秒、最大 10 MB；这些是接入依据，实施前应复核供应商当前约定。超限时说明原因，不静默截取。原素材应复制进应用管理的存储，避免用户移动源文件后失效。

音色档案不等于完成模型训练。初期通过每次生成携带保存的参考音频复用声音；永久音色 ID 只在供应商明确支持且实际取得时使用。

### 6.3 默认音色与单条覆盖

| 操作 | 影响范围 |
| --- | --- |
| 为角色首次绑定音色 | 后续章节及新加入剧本的该角色默认使用此音色 |
| 在剧本中修改一条音色 | 仅覆盖当前条，不修改项目角色默认值 |
| 修改项目角色默认音色 | 默认作用于后续新建片段，不自动改动已有章节 |
| 将新默认音色应用到当前章 | 显示受影响条目；用户执行后更新相应片段并标记待生成 |

片段保存自身已确定的音色选择，避免角色默认值变化后旧章节悄悄改变。批量应用新默认值时，默认保留用户做过的单条覆盖。

已被使用的音色档案不能直接删除其素材；第一版可将其归档并禁止新选用，仍允许已有章节播放和重做。更换参考素材时创建新的音色档案，避免无提示改变历史绑定。

## 7. 剧本工作台与前端布局

### 7.1 信息结构

- 左侧：项目名称、章节列表、章节状态；音色库与设置入口。
- 中间：当前章剧本列表，是主要工作区域。
- 右侧：按需展开的片段编辑、原文对照或角色详情。
- 底部：固定连续播放器，显示当前条、播放进度、播放／暂停和跟随播放开关。
- 顶部：章节标题、待确认数量、生成进度，以及随状态变化的主要操作。

空间较窄时，右侧详情改为抽屉，不挤压台词阅读区域。

### 7.2 剧本行内容

每行呈现序号、角色、音色、情绪／表演要求、台词、生成状态、试听与重跑。长台词允许换行；错误信息在对应行展开，避免大量全局通知。

音色显示“角色默认”或“本条指定”的来源提示。情绪采用常用预设加自由描述，例如“平静”“压低声音、警惕”“压抑愤怒”；不显示未经验证的情绪准确度或精确强度滑杆。

列表支持筛选“全部、待确认、待生成／更新、失败”。连续播放始终按章节完整顺序进行，不因筛选静默改变；当前条被隐藏时提供返回当前条的入口。

### 7.3 视觉与交互方向

界面以长时间阅读、试听和纠错为主，强调清晰文字、稳定布局、易识别状态与足够大的操作区域。状态同时使用文字和图标表达，不只依赖颜色；主要操作支持键盘访问与明确焦点。

Beautiful UI 可用于参考任务状态、表格与侧栏表达；React Bits 的动效仅用于必要反馈，避免干扰台词阅读。第一版没有明确 3D 需求，不引入 Three.js。

## 8. 生成与返工

### 8.1 生成方式

按配音片段分别请求生成，再顺序试听与合并。第一版采用单队列顺序处理，保留未来依据实测调整并发的空间，不预设供应商支持高并发。

提交任务时保存实际使用的台词、角色、参考音频、表演要求与模型配置，保证能够解释当前结果是按什么条件生成的。

显示已完成／总条数、当前处理条目、失败数量和已耗时。没有供应商真实进度时不伪造单条百分比或精确剩余时间。

### 8.2 状态与编辑规则

| 状态 | 含义 | 可用操作 |
| --- | --- | --- |
| 待确认 | 说话人等关键信息未确定 | 校对、选角色与音色 |
| 待生成 | 尚无音频 | 编辑、生成 |
| 排队中／生成中 | 已纳入当前任务 | 本章只读，查看进度 |
| 已生成 | 有对应当前设置的可用音频 | 试听、编辑、重跑 |
| 待重新生成 | 设置已变更，仍保存旧音频 | 编辑、重跑、明确标注的旧版试听 |
| 失败 | 最新生成未获得可用结果 | 查看原因、修改、重试；保留此前成功结果 |

“最新尝试失败”和“是否仍有可用旧音频”分别保存，不以一个失败状态抹掉已有产物。

### 8.3 单条重跑与安全替换

1. 用户修改音色、情绪或台词，条目标记待重新生成。
2. 点击重跑，暂停连续播放并记住播放位置。
3. 使用本次提交时的最新设置生成，本章暂时只读。
4. 检查返回结果非空、实际可解码并完整保存。
5. 成功后将新音频设为当前结果，保留上一版供恢复；失败则保留原结果与错误信息。
6. 解锁编辑和播放，不自动播放声音。

恢复上一版时一并恢复对应的片段设置，避免旧声音与新设置被误认为一致。仅需保留当前版与上一版，不在第一版建设复杂版本管理。

### 8.4 停止与故障恢复

“停止后续生成”停止提交队列剩余请求；已发出的请求可能仍完成，不承诺上游取消或停止计费。有效返回仍应保存。

普通单条失败可记录后继续下一条；鉴权、余额或持续限流等共同问题应暂停队列。网络超时可能意味着上游仍在处理，不能无限自动重试。

任务由服务端管理，页面关闭或刷新不直接取消任务。服务进程中断后，已保存音频继续可用；未完成且结果不明的请求标记待检查，由用户决定重新提交，不默认重复扣费生成。

## 9. 试听、暂停和滚动

- 支持单条试听与全章顺序播放；两者互斥，避免声音重叠。
- 常规暂停／继续保留音频内的当前位置。
- 重跑期间禁止继续播放；重跑结束后点击继续，从原暂停所在条的开头播放。
- 没有连续播放断点时，重跑后保持停止，可单独试听重跑条目。
- 重跑失败后可试听保留的旧版，但必须标注其与最新设置是否一致。
- 当前条保持高亮；开启跟随时将其滚动到列表中部附近。
- 用户主动滚动查看其他台词时暂时停止跟随，提供“回到当前播放”按钮。
- 连续播放遇到缺失音频或待更新条目时停下并说明原因，不静默跳过或播放过期音频。
- 最终生成未结束前不提供整章连续试听；剧本和进度保持可查看。

## 10. 间隔、合并与导出

### 10.1 间隔设置

片段间隔默认 0.5 秒。设置页提供新章节默认值，章节保存自己的当前间隔；修改默认值不影响已经制作的章节。当前章试听与导出共用该章的间隔值。

间隔指片段之间额外插入的静音，不包含生成音频自身的首尾停顿。第一版保留原音频停顿，不自动强裁剪；实际听感过长时通过重跑或后续明确的停顿编辑能力处理。

### 10.2 合并规则

- 使用当前有效音频，按剧本顺序合并。
- 只在相邻片段之间插入间隔，不额外追加最后一条后的间隔。
- 合并前确保没有缺失、待更新或进行中的片段。
- 统一音频格式、采样率及声道后合并，不直接拼接文件字节。
- 合并不触发新的模型生成；修改间隔只需重新合并。
- 文件生成成功后才更新当前导出记录，失败时保留此前可下载的导出文件。
- 片段替换、拆分合并、顺序或间隔变化后，将旧导出标记为“需要重新合并”。

第一版提供 WAV 与 MP3，内部优先保存 WAV；输出编码规格在实际接入与播放验证后确定。暂不宣称达到特定发行平台响度标准。若实测出现明显音量差异，增加必要的统一处理，并确保试听和导出均使用同一处理结果。

## 11. 模型与接口设计依据

### 11.1 两类模型职责

| 服务 | 职责 | 当前决策 |
| --- | --- | --- |
| 文本模型 | 小说分段、角色归属、别名匹配、角色简介、情绪建议 | 具体供应商与模型待选；需以真实小说样本验证 |
| 音频模型 | 根据台词、参考声音和表演要求生成片段 | 优先接入 Kunpo 的 seed-audio-1.0 已有调用路径 |

### 11.2 Seed Audio 接入边界

以下来自项目现有《Seed Audio 1.0 — KunpoAPI 接入与能力核验》文档，属于实施参考。本文没有重新调用模型或完成听辨验收。

- 请求端点为 `/v1/audio/speech`；优先使用 `text_prompt`、`references`、`audio_config`。
- 情绪作为自然语言表演要求进入提示词，不直接假设存在可用的 `emotion` 参数。
- 音色通过参考音频或供应商确认可用的音色 ID 指定；兼容字段 `voice` 不作为音色切换依据。
- 文档记录原生提示词最长 3000 字符，单次输出最长 120 秒；分段需保留余量，不能仅用字数换算保证时长。
- 当前路径返回音频二进制，不依赖它返回字幕、精确时长或实际扣费 JSON。
- 不承诺实时增量播放、远端取消、确定性复现或重复请求自动去重。
- 自然语言情绪控制已具备调用方式，但精确执行、跨句音色一致性与逐字正确性仍需听辨验证。

参考提示词可以包含：角色参考声音、必要的场景和表演要求、只朗读正文、不朗读说明、不添加音乐或环境音。前后文只作理解辅助，需明确不属于朗读正文。

## 12. 数据与实现建议

### 12.1 最小数据结构

| 对象 | 主要保存内容 |
| --- | --- |
| 项目 | ID、名称、创建及更新时间 |
| 章节 | 项目关联、标题、顺序、原文、间隔、制作状态 |
| 角色 | 项目关联、名字、别名、简介、性别及确认状态、默认音色 |
| 音色档案 | 名称、描述、参考音频路径与属性、可选测试样音、归档状态 |
| 剧本片段 | 章节关联、顺序、原文位置、角色、类型、朗读文本、音色及来源、表演要求 |
| 生成记录 | 片段关联、实际输入配置、任务状态、错误、音频路径与时长、当前／上一版关联 |
| 导出记录 | 章节关联、使用的生成记录及顺序、间隔、输出文件、是否需要更新 |

通过普通 ID、关联和数据库事务维护状态。第一版不引入内容哈希、冻结合同或额外基线系统。

### 12.2 建议技术方案

- 前端：React 与 TypeScript，优先使用常规表单、列表和浏览器音频能力。
- 后端：提供文本提取、生成队列、文件存储和导出接口；开发前确定语言，不为本工具引入多套服务。
- 元数据：首版单实例可用 SQLite。
- 文件：参考素材、生成片段与导出文件保存在应用管理的持久目录。
- 音频处理：优先复用 FFmpeg／FFprobe 完成格式检查、测时与合并。
- 队列：普通持久任务记录加单工作队列，暂不引入独立消息中间件。

先完成本地可运行版本；公司在线部署、统一登录和账号隔离另作部署阶段设计。若部署为多用户服务，项目与音色等资源必须按实际登录身份隔离，不能共享默认用户数据。

### 12.3 基础保护

- 服务凭据不下发到浏览器，不写入版本库或普通日志。
- 导入文件校验大小、类型、实际可读取性；失败时保留原有项目内容。
- 原文与音频作为用户内容处理，不允许其中的文本改变系统执行规则。
- 文本和参考音频会发送给所选模型服务，在相关生成操作处说明用途。
- 批量或单条重跑可能产生新费用；费用如只能估算，应明确标注估算，不能显示成实际账单。
- 删除项目等操作说明影响范围；删除共享音色不能破坏其他项目的已有产物。

## 13. 验收标准

| 场景 | 通过标准 |
| --- | --- |
| 小说提取 | 旁白、对白、心理独白可区分；没有无法解释的漏句或重复；能对照原文纠正 |
| 隐式对话 | 不确定归属可见且可修改，不将猜测静默写为已确认角色 |
| 跨章延续 | 第二章已有角色继承已确认默认音色，新角色单独配置 |
| 默认与覆盖 | 单条换音色不修改其他句子；改默认音色不自动改动旧章节 |
| 情绪与音色 | 人工听辨实际声音，确认台词、身份及表演效果；接口成功不等于通过 |
| 设置变化 | 改文本、音色或情绪后显示待更新，不把旧音频视为最新结果 |
| 单条返工 | 使用最新提交设置；成功替换，失败保留旧结果；可恢复上一版 |
| 播放控制 | 高亮与实际声音一致；暂停可继续；重跑完成后按约定从断点条开头继续 |
| 手动浏览 | 播放时用户可翻看其他片段，不被自动滚动反复拉回 |
| 队列恢复 | 刷新页面仍可查看任务；部分失败不丢失成功结果；服务中断后不盲目重复提交 |
| 合并导出 | 顺序及间隔与试听一致；末尾无额外片段间隔；输出文件可实际播放 |
| 产物更新 | 重跑或改间隔后旧导出显示需更新；合并失败保留此前导出 |

首轮样本建议包含：一段连续旁白、至少两名角色、无署名的轮流对话、心理独白、角色别名、短句和长段落，以及明显但不同的情绪要求。

## 14. 实施顺序与待确认事项

### 14.1 实施顺序

1. **验证核心音频链路**：用少量真实片段验证参考声音复用、情绪、逐字正确性、单条重跑和拼接；真实付费调用单独执行，不视为本设计文档已完成的工作。
2. **建立可保存的工作台**：项目、章节、角色、音色库、剧本列表及基础编辑。
3. **接入文本提取**：角色匹配、原文对照、待确认项及人工纠正。
4. **完成制作闭环**：批量生成、任务恢复、连续试听、重跑、安全替换和章节导出。
5. **用跨章样本验收**：根据真实制作中的问题调整分段、声音一致性及交互。

### 14.2 开发前需落实的事项

- 小说解析所用文本模型及服务配置。
- 实际部署运行方式：首版建议本地 Web 工作台；在线版另行接入部署与登录。
- Seed Audio 的声音一致性、情绪服从与短句效果听辨结果。
- 实测生成耗时、并发限制、失败后的计费与重试处理。
- 目标播放器中的 WAV、MP3 兼容性，以及是否需要首版即处理音量差异。

以上待确认项不妨碍界面与数据设计推进，但不能在缺少证据时写成模型已支持或功能已通过验收。
