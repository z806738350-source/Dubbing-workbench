## 0. 执行结论与使用方法

**可以开始增强阶段研发。需要补的是研发合同、数据兼容规则和阶段出口，不是重新讨论已经定稿的产品定位。**

执行顺序如下：

`E0 基线与执行准备 → E1 声音创建完整闭环 → E2 生成单元兼容层 → E3 多人干声对戏 → E4 场景生成 → E5 分项发布与交付`

声音创建可独立完成、验收和交付，不依赖对戏完成。经素材和费用授权后，多人干声的最小音频对照可与 E1 并行；其正式集成依赖 E2。场景模板小样也可提前探索，但不能代替 E4 的事件、版本、恢复和界面实现。

不把“所有历史场景绝对验证完毕”作为无限期不开工的前提。发现基础模式新阻断缺陷时按影响处理，不能自动冻结互不依赖的全部任务；已经关闭的整改不无故重新打开。

- **【沿用】**：原三份定稿已经规定，执行者不得悄悄降低要求。

- **【资料依据】**：供应商或原厂公开说明；不等同于项目实测成功。

固定提交中的设计文档保留了制定时“尚未实现”的历史状态。它不是当前代码完成度的证明；本次实现落点来自源码，历史复核结论来自当前对话，二者分开使用。

### 1.2 本阶段必交付范围

| 能力 | 必交付行为 | 不可替代为 |
| --- | --- | --- |

### 1.3 既有保护不可退化

正文和声音导演层分离；显示名不替换正文人名；参考和表演不改角色永久事实；AI 建议须采用；生成成功不自动检查通过；本章服务端只读；停止只处理未获得发送资格的请求；结果不明不自动重发；旧产物补登记不复活结束批次；母版与导出同源；音频匹配与审核资格分离；草稿归属、遗留处理与精确保存回执继续有效。

### E0：基线、授权与测试环境

2. 使用独立数据目录运行。先对用户工作区做停服完整备份及恢复验证，不能用真实工作区直接试迁移。
3. 运行当前完整测试和构建，保存原始输出、环境、版本及退出码；复核历史测试的适用范围，不用测试数量代替断言。
4. 建立阶段任务单，列明文件落点、迁移步骤、验收 ID 和依赖。这里是开工准备，不要求再送审一套同等篇幅的新方案。
5. 将真实API素材、调用用途、模型与费用边界记录为授权项；无授权时照常做本地开发、模拟测试，不调用真实接口。

**出口 G0：**基线可重现，独立数据可恢复，本地改动受保护，测试与费用边界清楚。仅环境故障造成未运行时如实记录，不冒报通过。

### E1：声音创建完整闭环

**任务 E1-01—E1-06：**候选会话与任务目标；零参考模板与预检；候选列表和试听；幂等保存参考资产；绑定／跨句复用；候选异常、关页与重启恢复。

**出口 G1：**用户能在工作台完成描述至真实配音复用的全流程；候选与已有上传参考路径共存；本节对应自动／浏览器测试通过；真实样本具备并由用户判断声音身份。仅接口能返回文件不算声音效果通过。

### E2：生成单元兼容层

**任务 E2-01—E2-05：**单元与版本数据；旧单条兼容迁移；统一实际请求及审核依据；编排解析；备份恢复／清理／草稿兼容。

**出口 G2：**所有旧有效单条仍选择相同音频、模板和检查记录；没有模型请求；旧章试听和导出不重复、不漏播；数据库升级中断可恢复；组功能尚未开放也能运行纯单条模式。

### E3：多人干声对戏

**任务 E3-01—E3-06：**连续选择与冲突预检；待生成组；多参考提示编译；生成并启用原子切换；组级检查和返工；拆组与真实对照。

**出口 G3：**已完成组级状态、恢复、编排和浏览器测试；实际对照完整记录正文、身份、衔接与返工代价。实验入口默认由用户主动开启。正式推广条件见第 14 节，不以“HTTP成功”替代。

### E4：场景生成

**任务 E4-01—E4-06：**事件模型与编辑；AI 场景建议及采用；锚点过期和冲突预检；场景模板；干声／场景双版本；混合场景样本和原文核对。

**出口 G4：**事件不会偷改正文；修改后正确失效；已有干声不被场景重跑挤掉；切换不隐式生成；场景全流程和真实小样均有结果记录。

### E5：分项发布与交付

**任务 E5-01—E5-05：**全量回归；迁移与回退演练；目标浏览器验收；文档与样本索引；逐项启用和远端发布核对。

**出口 G5：**每项的工程、接口、听辨及开放状态分别可查。允许只发布已验收的声音创建，其他项保持实验或关闭；但未完成项目必须留明确下一步和证据，不能宣称三项全部完成。

## 4. 数据关系与唯一真实来源

本节为【新增执行约定】，实现字段可等价命名。必须保留语义，不要求照抄为某种ORM或统一大表。

### 4.1 建议对象

| 对象 | 最小必要信息与职责 |
| --- | --- |
| `VoiceDesignSession` | 稳定ID、描述、样文、模板、模型、修订、候选关系；不是小说章节 |
| `VoiceCandidate` | 会话／尝试ID、实际输入、原始文件、技术状态、参考规格检查、保存的音色ID；成功不代表已入库 |
| `GenerationUnit` | ID、chapterId、single/group、有序成员ID、成员关系修订、活动／待生成／已解除状态 |
| `UnitVariant` | unitId、dry/scene、目标设置及版本；独立 current/previous/approved 引用和检查依据 |
| `GenerationAttempt` | 目标类型和ID、固定输入、完整提示、参考顺序、提交阶段、结果、异常、时间与产物来源 |
| `AudioRecord` | 单元／候选来源、实际请求快照、成员和槽位映射、原始音频、技术元数据；历史记录不可覆写成另一请求 |
| `SoundEvent` | 类型、描述、锚点、基准快照、依据、采用状态、有效性；不保存另一份可独立修改的朗读正文 |
| `ChapterArrangement` | 实际生效的有序单元、类型、音频引用、编排版本；待生成目标不得假冒当前选择 |

候选是否复用现有 audios 表或独立表由执行者决定；必须有显式 `targetKind`，不得依赖“缺少 segmentId 就一定是试音”这种分支。任务、声音引用扫描、删除、快照、恢复和备份都必须识别新类型。

### 4.2 逻辑台词与音频选择分离

【沿用】正文、角色归属、单条实际音色、表演要求和来源沿革仍属于逻辑台词；组只是声明这些台词共同生成。[D01 §17.5]

【新增执行约定】E2 完成后，当前播放选择以单元版本和章节编排为唯一权威来源。旧 `segment.current/previous/approved` 若为旧接口兼容继续返回，只能是受控投影或事务内维护的兼容镜像，禁止成为第二套可独立修改的真实选择。

每条有效台词可保留其 single 单元。组成活动组后，这些 single 单元的干声仍存在但不同时进入当前编排。组状态与音频技术状态分开，不能用 `job.success` 推导“组已启用”。

### 4.3 覆盖不变量

对当前章有效台词集合，每条在实际编排中必须出现且只出现一次；成员展开顺序与当前章顺序一致。排除片段不进入朗读集合，但其原文排除记录仍参与内容完整性判断。

组的成员必须是同章按真实顺序连续的有效台词；不得越过筛选隐藏的有效台词。首轮将已排除片段也作为组选择边界，避免组顺序和事件语义含糊；这是本计划的保守执行约定，不是供应商限制。

待生成组与活动组均不得相互覆盖成员。此约束须在服务端事务内验证；两个页面同时创建时只能一个成功。single 单元的历史保留不算组间重叠。

### 4.4 实际请求相等与审核相等

实际请求比较至少包括：模型／适用路由、完整编译提示、有序参考资源和有效输出参数。对象键顺序无关，数组、台词和参考顺序有意义。无参考候选用空参考序列，不虚构 voiceId。

参考资产在被引用后不得原地更换声音内容而仍冒用同一版本。允许用资产版本或导入时内容摘要表达身份；不要求每次界面轮询重新计算全部文件摘要。

审核依据除音频ID，还包含当前正文、角色归属、成员关系、类型和必要表演／事件设置。请求等效只能复用音频，不能绕过角色决定、用户检查和原文覆盖条件。纯显示名变化不改变请求槽位；正文中的真实人名始终原样保留。

### 4.5 修订职责

编辑修订、项目文本上下文修订、成员关系修订、场景设置修订、编排修订各负责自己的变化。可用快照代替部分独立计数，但必须表达同样的冲突检查。

任务进度、文件接收、候选登记和成功产物登记，不得推进会使同批后续请求失效的用户编辑修订。单纯全局资料变化不自动重跑已确认音频。组中改角色但实际参考相同，仍检查审核资格，不能自动恢复通过。

## 5. 迁移、备份与回退

### 5.1 迁移前

停服并确认无其他进程使用数据目录；对数据库和所有素材做共同备份，再在新目录恢复验证。记录模式版本、记录计数、关键引用、文件清单和摘要。备份不包含密钥。

在独立副本上准备至少五类夹具：正常完成章；含历史版本／需返工章；结束unknown但有正式音频的任务；遗留草稿／保存冲突；缺失或已删除参考但已有有效成品。

### 5.2 迁移过程

新增明确的模式版本和迁移日志；迁移可重复执行且不重复建单元／音色。数据库结构和记录映射尽量使用短事务；文件复制用临时文件、检查、原子改名，并保留可恢复的登记依据，不把跨文件操作假称为数据库原子事务。

旧片段映射 single 单元，旧当前／上一版／最近通过版映射 dry 选择，保留旧音频ID与旧检查依据。旧输入、提示和模板不改写；旧记录缺少新字段时通过带版本的适配器解释，不伪造历史数据。

旧母版可以按原始映射兼容读取；确需新映射时只做本地重建。不得为升级而付费重录。迁移完成前不开放新写入口，任何一步失败不能留下界面可编辑的半迁移状态。

### 5.3 新老写路径

新版服务启动时检查支持的数据模式，防止不支持的模式被继续写入。不得让旧程序直接打开已经升级的新数据库并假定它能理解新对象；回滚应恢复对应旧备份到另一目录，使用匹配代码启动。

新功能开关关闭不等于删除数据。仅停止新建／生成能力时，已有单元、音频仍可查看和导出；有活动组的工作区不能通过关闭开关静默切回单条。

### 5.4 草稿兼容

不得清空或重命名浏览器中的既有片段草稿来完成迁移。段ID不变；章级修订若发生必要变化，旧草稿可以进入待核对状态，但内容必须可取回。

新候选、组指导和事件草稿采用带对象类型及版本的键／数据结构。不得让 `listDrafts<Segment>` 将单元草稿误读成包含 `config` 的片段。保留活动页保护、逐份遗留处理、基于精确写入回执的续写衔接。

### 5.5 备份与清理同步升级

新表不等于新文件自动受保护。候选未入库、非活动组、dry/scene的上一版和最近通过版、已结束unknown的正式产物，都必须纳入引用检查。

清理只处理经完整引用图确认的无引用文件；不自动删历史版本、不把 `.part` 当成功、不按年龄清除未知产物。新增表的记录应纳入恢复一致性核对，不能只比对旧表数量。

**回退规则：**保留升级后数据副本和升级前备份；用户升级后的新制作结果不能因回退被覆盖。先说明切回旧备份意味着哪些新操作未在旧库中，再执行明确选择。

## 6. 声音创建：完整实现约定

### 6.1 用户流程

入口位于音色库，与“上传参考”并列，而不是替代上传。

`新建声音描述 → 核对样文与本次生成范围 → 生成一份候选 → 试听 → 保存为音色 / 再生成 / 放弃 → 用户选择角色绑定 → 新文本试音或章节配音`

【新增执行约定】初次默认每次点击生成一份候选，不自动生成三份。允许连续保留多次候选供比较；每次重试是新的明确请求。候选尚未通过音色复用听辨时，显示“待验证”，不能靠文件非空自动写“已稳定复用”。

声音描述可写年龄感、声线、口音和气质；这些是声音设计，不自动写回角色的年龄、性别或人物事实。沿用参考素材使用授权记录，不将“已生成”推导为任何未核实的商用许可。[D02 §4；D03 §3.1]

### 6.2 无参考任务

候选生成允许没有参考；不得为了复用旧 `voice-test` 分支虚构空音色或小说片段。已有上传参考后的测试样音继续使用原路径，不依赖新候选功能。

会话在提交前持久保存；请求包含固定描述、固定短样文、模型、候选模板、有效配置和命令ID。描述编辑不能改写已经发送尝试的实际输入。旧候选迟到只能归原会话／原尝试，不成为新描述的自动推荐或当前选择。

独立会话不锁无关章节。相同会话不并行重复派发相同命令，服务层检查重复提交；重试unknown需明确风险确认。

### 6.3 候选文件与入库

候选先保存为真实产物并通过技术检查。符合参考规格且用户选中后，保存到音色库；重复点击“保存此候选”或保存响应丢失后重试，应返回同一个新音色ID。

本阶段保持上传参考的现有格式范围，不因接口支持更多格式就顺带扩展全部上传器。生成的候选优先沿用工作台WAV输出。时长或大小不合格时保留候选供查看，禁止直接绑定为参考；提示用户重新生成较短候选。自动裁切、自动压缩后冒充原候选不在本轮范围内。

保存参考可复制到音色目录或采用明确共享资产引用。无论选哪种方案，必须保证候选会话放弃、旧候选清理、音色停用／删除不会误删另一个仍有引用的文件。

保存音色记录含来源候选ID、原描述、样文、实际提示／模型／模板及创建时间。命名相同不是自动去重依据；同一候选唯一保存才是。

### 6.4 成功条件

工程：刷新、关页、重启、重复命令、登记失败、保存失败均可恢复；用户能正常使用新音色。

效果：候选本身听感符合描述；用其生成多句不同文本时，对照候选判断声音身份。记录成功和失败的全部尝试；用户选中的最终参考没有已知的读错样文、身份混杂或明显不可用问题。有限样本通过不写成长篇永久一致性保证。

## 7. 多人干声对戏：行为矩阵

### 7.1 建组预检

用户选择同章连续台词，预览实际纳入的全部成员和当前设置。服务端检查：成员仍存在且有效；正文／身份决定完成；未与其他待生成或活动组重叠；同一角色的实际参考一致；各成员有效数值配置一致；模板／模型差异已明确解决；生成提示合法。

参考配额按去重后的实际资产计算，旁白如使用独立参考同样计入。相同参考不等于同一角色；说话者槽位按首次出场，参考数组按本次实际映射稳定排列。[D02 §5；D01 §17.5]

发现不同单条覆盖时展示冲突，用户取消、改相关台词后重新建组，或另选范围；不得“取第一条”“取角色默认”静默统一。首轮不增加复杂组级数值覆盖机制。

前端检查成员的本机未保存草稿，包括其他页与遗留草稿。服务端检查的是已保存数据、修订和组约束，不能声称服务器能发现所有浏览器中尚未提交的草稿。

### 7.2 操作与结果

| 操作 / 情况 | 当前编排行为 | 检查及付费行为 |
| --- | --- | --- |
| 创建待生成组 | 原 single 编排保持 | 不调用模型，不改变旧通过状态 |
| 生成并启用本组 | 成功且目标适用时一次切换为组；单条文件保留 | 一次组请求；新组待检查 |
| 首次成组失败／unknown | 原 single 编排保持，明确组未启用 | 不自动再试，不显示当前已是组 |
| 活动组相同设置重跑失败 | 旧组选择保留，按其原有效性／检查状态处理 | 失败不自动抹掉可用旧声音 |
| 活动组先改成员正文／参考／表演再重跑失败 | 旧组仅作明确旧版试听；当前目标未完成 | 不偷偷回退单条伪装新结果 |
| 改角色但请求实际等效 | 可复用声音，重新判断角色审核依据 | 不强制付费，不自动检查通过 |
| 解除分组 | 按预览切回匹配 single；缺失项待生成 | 不裁切混合音频，不自动补生成 |
| 解除后旧结果迟到 | 归历史，不重新激活组 | 不改当前音频和通过状态 |

### 7.3 成员与修改

活动组成员仍可在解锁后修改文字、角色、音色、表演，但提示受影响的整个组及版本。拆分、合并、排除或改变成员结构前先解除组；不要直接在组记录里插删成员而复用旧音频。

待生成组要取消／重建成员方案时也需解除其成员占用，保留历史任务。更新成员设置与目标快照时要原子处理；不能部分写完便接受生成。

### 7.4 播放与母版

章节编排选择组音频一次，展开逻辑成员用于覆盖校验，但不能展开成多次播放。额外间隔仅放在相邻实际生成单元之间；组内不按台词行再插静音。

没有可靠映射时，只高亮组并显示组内台词，不把整段时长按字数分配成假时间戳。重跑后的断点从组开头继续。[D01 §17.2；D02 §5.4]

【新增执行约定】本阶段保持现有单声道母版，不承诺左右声像。场景和组原始响应可以保留原元数据，但最终试听与导出必须同源使用明确的处理配置。若真实样本证明必须立体声，再独立提出兼容调整；不得静默改变所有旧母版格式。[C04]

### 7.5 拆组预览

列出每条将恢复的音频、是否匹配、检查状态，以及仍需生成的条目。列出会退出当前编排的组内场景声音。优先恢复分组前保存的 single 干声选择；不存在时不能猜一个历史文件或自动裁切组音频。

拆组导致缺音时，章节暂不能整章播放或正式导出。保留可单条试听的完整资源和历史组。用户明确发起补做后才产生新费用。

## 8. 场景生成：事件与双版本

### 8.1 表达范围

声音事件分为持续环境、一次性音效、音乐背景；只用必要的自然语言描述，不建设完整音频时间线。

【沿用】“门外传来两下敲门声”仍保留朗读。声音事件可以叠加，不能替代原句；“某某说”也不自动删除。身体状态不自动升级为脚步、衣物或喘息等额外声音。[D03 §3.2—3.3]

### 8.2 事件数据

最少保存 `unitId`、事件ID、类型、描述、采用状态、目标成员ID、之前／期间／之后、目标文本／角色／类型及成员关系的基准依据。

【新增执行约定】持续背景可用开始／结束两个语义锚点表达；整组背景以首成员之前到末成员之后为范围。该范围是生成意图，不是精确毫秒区间。首轮不支持跨生成单元连续背景，避免承诺未验证的接缝和相位连续。

事件状态建议分开记录：`draft/adopted/removed` 与 `valid/needsReview`。已采用但失效的事件不能被自动忽略后照常生成，应阻断相关场景请求，等待重新确认或明确移除。

### 8.3 AI 建议与人工输入

用户未启用场景时，分析只提出干声表演，不偷偷创建事件。启用后，AI 返回目标ID、事件描述、依据类别和出处，不能重新输出另一份台词或自己分配参考编号。

采用继续执行章级与共享上下文修订检查，默认勾选后一次应用。依据类别保持“原文明示／上下文推断／创作建议”。人工加入的事件标识为用户创作选择，不伪造原文出处。建议的采用不等于生成，也不等于声音已检查。

### 8.4 事件失效

目标文字、角色、类型、组成员顺序或归属改变时复核；拆分、合并、排除、移出组后不能靠相似文字搬移。纯显示名修改不应失效。场景事件变更只影响相关场景版本，不让无关干声失效。

持续事件任一边界失效即整体待核对。两句同文但ID不同，不能用字符串匹配选择锚点。

### 8.5 干声／场景选择

每个单元分别保存 dry 和 scene 的当前、上一版、最近通过引用及设置。连续多次场景重跑不得挤掉干声引用。

切换时区分三种情况：

1. 目标类型已有匹配音频：用户选择后本地切换并重建母版；审核依据一致才能复用通过。
2. 只有不同设置旧版：展示设置差异；用户明确恢复，不能自动撤销后来纠正的正文或角色。
3. 没有目标版本：提示本次生成范围、费用与返工单位；用户发起后才请求。生成成功前保留原实际编排，目标类型显示未启用。

“保留干声”仅指保留已有文件。不要求场景请求之前必先付费做干声；用户需要两种版本时分别明确发起。[D01 §17.3/17.5]

### 8.6 单条场景与成组场景

【新增执行约定】同一生成单元体系允许 single 或 group 的场景版本，不为单条场景另起一套播放器。单条场景修改重做该单元，成组场景修改重做整组；均不承诺局部无损替换声音事件。

## 9. 请求适配与提示编译

### 9.1 当前接口核对摘要

【资料依据，2026-10-01核对】Kunpo 音频路径为 `/v1/audio/speech`，返回二进制；`text_prompt` 上限3000字符；参考音频至多3条，每条不超过30秒／10MB；生成上限120秒；音频与图片参考互斥；`instructions` 仅缺省回退，`voice` 不用于 Seed 换声；当前接口不返回字幕JSON。[K01]

上述是文档约束，不是本计划测得的能力。原厂说明支持文字塑声和联合场景创作，但不构成本项目声音一致性、逐字正确性或混合音频局部编辑保证。[K02]

其他格式／参数、本轮收费规则和账户倍率由执行者在真实调用前再次核对；本计划不据宣传声明增加续写、分轨或取消参数。

### 9.2 模板隔离

保留 `dry-v1` 实现不变。建议新建 `voice-design-v1`、`dialogue-dry-v1`、`scene-v1` 等项目模板ID；这些是程序内部标识，不是供应商参数或官方语法。

不要单纯修改全局 `templateCatalog.current` 使全部新片段默认获得组模板。按任务类型／单元模式选择默认模板，已有对象保存有效版本。模板升级要明确预览和应用，引用中的旧实现必须可继续调用。[C03；D03 §5]

### 9.3 编译步骤

1. 读取固定修订的已确认朗读正文，不要求文本模型重写。
2. 解析稳定角色ID，分配本次说话者槽位；正文中的姓名不替换。
3. 根据实际参考资产建立有序数组和 `@音频N` 映射。多个角色共用参考时不合并角色槽位。
4. 按“组级默认 → 本条明确例外”编译表演；内部矛盾需用户处理，不把相反要求并排交给模型猜。
5. 只编入已采用且有效的事件；干声和启用事件的确定冲突在调用前阻断。
6. 合并为唯一完整 `text_prompt`，验证总字符和有效参数，保存预览及最终请求快照。

候选没有参考时，提示不得出现虚构的 `@音频1`。成组时每条正文在编译输出中按顺序保留；局部重音若引用正文词句须标为说明，不当作追加台词。

### 9.4 请求体边界

供应商请求仅显式组装已确认支持的字段。内部 `unitId`、成员ID、事件状态、任务类型、检查记录、模板ID不作为猜测的模型参数发送。

本轮继续固定工作台原始WAV输出与既有有效采样配置；可编辑数值只包含已支持的语速、音量和音高。不得重新使用不受控对象展开覆盖固定配置。候选省略无参考字段或使用适配器核验过的空数组形式；两种形态先在模拟与真实最小请求验证，不自动失败重试另一形态。

最终提示超限时阻断并展示如何拆组／缩减说明；不能截断正文或自动增加多次付费请求。时长预测只做警示，不以中文字数换算当作时长保证。

### 9.5 实际结果边界

保存真实响应、元数据和技术结果后，仍需检查朗读内容、角色身份、表演及事件。文件可解码不等于内容完整。字幕、转写和模型自评如以后接入，只能辅助，不能取代原文覆盖校验与听辨。

## 10. 任务、费用风险与恢复

### 10.1 共用任务骨架，不混淆目标

生成任务携带明确 `targetKind` 与目标ID：候选会话、音色测试、single、group；渲染任务继续是纯本地母版／导出。不得将候选伪造成小说片段，或用 `null voiceId` 进入必读声音记录的分支。

每个任务固定命令ID、输入快照、目标／成员修订和模板。重复同一命令返回同一任务；同一命令ID被用于不同有效载荷时拒绝并提示冲突。用户明确重新生成是新命令，不能误复用旧结果。

### 10.2 发送资格

队列入队时固定内容；实际发送前检查最新停止、服务关闭、路由阻断、目标有效性和全部参考状态。异步参考检查结束后，在最终发送资格事务中再次检查，不只在异步检查之前看一次。

候选无参考时略过参考校验，但仍检查会话是否放弃、描述修订和停止状态。多人组必须检查所有参考，不只第一个。归档允许已有绑定按原规则继续；停止未来使用阻止未发送请求；删除等待读取及在途任务结束。

一旦进入定义好的发送阶段，不能承诺远端撤回或免计费。停止旧批次并解锁后，继续操作建立新命令并预检当前内容，旧批次不得复活。

### 10.3 异常矩阵

| 场景 | 必须保留与显示 | 禁止行为 |
| --- | --- | --- |
| 入队预检失败 | 原内容、原选择、具体问题；无付费请求 | 部分成员已生成后才告知整组配置不合法 |
| 参考检查期间停止／关闭 | 未发送已停止 | 异步检查后仍无条件发送 |
| 权限／余额／限流等共享错误 | 该路由后续派发停止，用户检查后重启新命令 | 在所有片段上反复撞同一共享错误 |
| 请求已发送但连接中断 | unknown与可能计费，保留输入及残留文件 | 自动重发或当作明确未计费 |
| 完整正式文件已落盘、登记失败 | 重启补登记原尝试；结束任务不复活 | 因任务结束而漏找回；自动覆盖新版 |
| 只有可部分解码 `.part` | 保留待核对 | 仅因可解码就提升为完整成功 |
| 组成功返回但组已解除／成员变化 | 历史产物，标明未启用 | 迟到结果重新启用组 |
| 场景重跑失败 | 保留已有版本及其真实有效性 | 以旧干声冒充已完成新场景 |
| 母版／导出缺失且源音频完整 | 本地重建 | 引导重新付费录制 |
| 候选保存响应丢失 | 查询或重复同一保存命令返回相同音色 | 同一候选生成多个重复音色 |
| 备份／存储空间不足 | 明确失败，已有文件不清除 | 自动删历史结果腾空间或改口称成功 |

### 10.4 费用与授权

本计划不是付费授权。执行者应记录适用授权的素材、路由／模型、调用目的、次数或费用边界及何时需要再次确认。已有明确授权可在其原范围内使用，不必重复索要，但不能扩展为无限实验。

入队预算需要原子预留本地调用额度，防止并行任务共同超出批准上限。unknown保留其可能已用额度，不因客户端没拿到时长就算零费用。估算不是硬性账户账单；缺少可靠账单能力时用已批准的最大调用次数与单次范围控制，并明确限制。

每个失败样本保留结果；下一轮真实实验只补必要部分。没有明确预算或素材权限时，继续模拟开发，不自动发送用户小说、私人录音或以前测试目录。

## 11. 草稿、界面与操作一致性

### 11.1 必须延续的编辑保护

每类可编辑对象的草稿独立暂存、按页面区分；遗留草稿可逐份查看处理。生成前检查选中单元及其成员的相关本机草稿，提供定位处理入口，不能只报“有草稿”但找不到。

保存回执包含这次写入实际确认的修订；保存期间续写要承接自身成功保存，而不是盲用最新轮询版本。切换片段／组、关面板、刷新、复制页和响应迟到均不能清掉新输入。

新场景事件和组指导如果有服务端自动规范化，续写应比较本次提交、实际保存结果与剩余用户改动；不能只机械抬高修订而忽略角色／配置被服务端明确调整。真实跨页冲突仍拒绝，保留两边数据供核对。

### 11.2 显示与按钮语义

角色和正文保持主要信息层次。单条行可显示“来自对戏组G”“场景版本”，但不铺满高级参数。额外事件用面板或渐进展开。

生成按钮需区分“生成候选”“生成并启用本组”“重跑本组”“生成场景版本”，并在确认处显示受影响成员及费用范围。缺失版本不可用“切换”暗中执行生成。

待生成／生成成功待检查／已启用／版本已过期／结果不明是不同信息；图标和文案不能把它们合并。

### 11.3 播放和检查

播放会话绑定实际单元、版本和音频记录。相关编辑、模式切换、拆组或其他页面更新使会话失效时停止旧声音；纯显示改名不打断。

检查提交包含用户看到的实际音频和审核依据。组级通过不复制成成员 single 旧音频的通过；单条旧通过也不自动通过组音频。整章确认必须检查当前有效编排及正文／身份条件。

### 11.4 目标浏览器

至少在用户实际使用的Chrome环境执行真实交互并记录版本、页面origin、屏幕尺寸及数据目录；不能把模拟Storage／Locks或状态夹具结果记成Chrome回归。

本机不同端口对应不同站点存储范围。启动与目录相关改动本轮仍不混入；如测试需要改变origin，应明示浏览器草稿并非自动跨origin迁移，不清旧origin数据来掩盖问题。

## 12. 正式导出与检查资格

【沿用】保留四层门槛，不只检查文件齐全：[D01 §10.4]

1. **内容就绪**：有效朗读非空，原文覆盖与显式排除成立，当前剧本与来源版本相符。
2. **身份决定完成**：必要角色／声音核对已完成；未知性别或简介不因此阻断。
3. **音频与编排就绪**：每条被当前单元覆盖一次、顺序正确、所选变体匹配、文件完整、母版对应当前编排。
4. **检查就绪**：没有当前需返工项，音频和审核依据相符，章节确认有效。

新增要求：待生成组不算当前组；有失效事件的目标scene不算已完成场景；dry通过不能代替scene检查。可以一次确认当前待检查音频，不增加逐句强制采用。

已有音频有效时，参考被停止或删除不应阻止纯本地导出。相反，单纯所有文件存在不能绕过角色未确认、空集合、漏文、重复覆盖或失配音频。

## 附录 A：起步提示示例（本计划编写，尚未音频验证）

```text
成年人的中低声线，温和、清楚，略带颗粒感，吐字自然。

清晨的风吹过窗边，我把桌上的书合上，准备出门。

[声音呈现]
单人清晰干声，无音乐、环境声或额外音效。
```

不出现参考编号，因为本次候选不使用参考。生成后先核对文件和内容，再由用户决定保存。

### A.2 多人干声

```text
[任务]
按下面顺序生成一段中文双人对白。只朗读编号后的正文一次。
编号、说话者标签、标题和表演说明都不读出。

[角色参考]
说话者 A 使用 @音频1 的声音身份。
说话者 B 使用 @音频2 的声音身份。

[互动]
两人轮流说话，不重叠。衔接自然，不额外添加回应或台词。

[逐条正文与表演]
1. 说话者 A；低声询问：你听见门外的声音了吗？
2. 说话者 B；冷静回答：听见了，先别开门。
3. 说话者 A；稍显紧张但吐字清楚：那我们现在怎么办？

[声音呈现]
清晰干声，不生成门外声音、音乐或其他音效。
```

真实提示由程序从已确认成员编译。此处角色、参考映射只是示例。组内间隔来自生成结果，不能在每行再追加章节间隔。

### A.3 场景版本

以同一组已确认正文和角色映射为基础，将呈现要求改为用户采用的场景设置，例如：

```text
[已采用声音事件]
对应第2条正文结束之后，出现两下轻而短的敲门声。
敲门声不要盖住对白，不增加脚步声、喘息或音乐。

[声音主次]
对白清楚，音效次要。保留全部正文，不用敲门声替代任何台词。
```

程序内部仍用成员ID和基准修订保存事件；“第2条”只是本次编译时的局部位置。不能因用户拆组后仍有另一句类似文字，就自动把事件搬过去。
