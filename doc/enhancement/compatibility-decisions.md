# 增强阶段兼容约定

本次沿用《增强阶段研发执行计划 v1.0》，没有改为多轨编辑，也没有增加自动裁切、猜测字幕时间或自动付费补齐功能。实现采用现有 SQLite 表、事务、文件检查、任务和浏览器草稿机制，没有增加依赖。

- `units` 区分逻辑台词与实际生成单元；旧片段以同一 ID 映射为 single，原记录、音频、模板及检查保留。group 按成员稳定 ID 保存，待生成时继续使用原单条编排，首次适用成功后原子启用。
- dry/scene 分别保存指导、当前/上一/通过版本和检查；实际章节编排每个成员只覆盖一次，组内不追加单条间隔。没有可靠时间映射时只高亮整组。
- `voiceSessions` 保存描述与候选目标，候选不虚构音色或片段。选定的具体音频复制保存成参考资产，不训练永久音色，不自动绑定角色。
- `events` 使用稳定成员 ID 与语义位置；正文、身份或范围改变后复核，纯显示名不改变锚点。手工章以当前正文作为可核对来源；多段依据分别逐字核对，不把不相邻引文伪装成连续原文。建议保持审阅、勾选、一次采用。
- 原 `dry-v1` 实现保留；新模板按候选/对戏/场景限定范围，普通修改和重跑不自动升级模板。
- 保存继续使用本页归属草稿及本次精确回执。新建对象期间续写先安全移交到新稳定 ID，再转为更新；关页遗留可逐份查看、恢复或放弃。
- 已发送的 unknown 保留可能计费及本地用量，不自动重发。结束任务的完整正式文件补登记为原尝试历史，须明确选择，不复活旧批次或覆盖新结果；`.part` 不晋升。

## 迁移、备份与回退

迁移在事务中执行；重复执行不重复创建 single。新旧表及候选、组、场景、正式结果、残留文件均纳入备份与清理引用检查。回退使用升级前备份恢复到新目录，保留升级库。

原 081314d 程序不读取模式版本，单独增加 metadata 无法阻止它直接写升级库。为满足计划 MR07，升级库使用 SQLite 原生写触发器检查当前连接注册的模式支持函数；旧连接仍可读和备份，但写入失败。匹配的新程序可以正常写入，升级前备份没有该约束，可由旧程序恢复运行。这项约束防止旧程序绕过生成单元写入导致重复编排；没有增加哈希或外部服务。

原本机目录、启动方式及未发布修改单独保留，不混入 GitHub 增强发布。不同端口有不同浏览器草稿；测试使用隔离 origin，不清理用户原 origin 的存储。
