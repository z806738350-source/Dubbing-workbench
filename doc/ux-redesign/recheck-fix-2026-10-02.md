# 生成范围重新核对：迟到响应补修

日期：2026-10-02。基于 `357cf09d052e5fed4f698ef37da1289db2d63cc9`，继续原 `codex/ux-redesign-v1-1` 分支内部试用。

## 问题与实际行为

审核方指出：重新核对生成范围时，关闭面板只清除了前端状态，等待中的免费读取仍只按章节 ID 判断有效。同章的旧响应因此可能重新打开面板，或覆盖后来打开的另一句计划。不是供应商等待，也没有据此证明实际配音费用或音频错误。

本次修复后：关闭、切章和新生成入口立即使上一操作失效。旧章节、旧计划、旧错误和旧授权回调不再更新新面板；正常重新核对仍展示更新后的范围，配音仍需明确点击开始。

## 实现范围

仅调整 `src/App.tsx`，复用现有 React ref 与保存协调器，无新依赖、接口、确认步骤或后端改造。

- 生成与重新核对共用一枚内存操作序号。重新核对在首次读取前取得身份，并沿章节读取、刷新、保存屏障与免费计划计算传递，不在迟到后重新取得操作权。
- 关闭、切章、空项目切换与新项目进入清章时同步失效。每个等待结束后、错误显示前检查当前身份和章节。
- 新的普通生成入口清除旧面板；正常重新核对保留当前组件的失效/更新提示。旧授权及额外费用选择回调不能恢复旧计划。
- 保存等待中取消的操作不提交；已经明确发出的请求仍保留原组合操作 ID、回执和任务刷新，其迟到结果不能关闭新计划。

原有修订、编排、草稿、授权、结果不明费用确认与供应商预检保护保持完整。前几轮已关闭的工程和视觉整改没有重新打开。本次未修改 `main` 或 `NBchitu/layerforge`。
