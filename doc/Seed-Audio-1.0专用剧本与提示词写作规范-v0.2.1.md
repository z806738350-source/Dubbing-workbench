## 1. 设计结论：保留正文，增加声音导演层

采用“原文 → 忠实朗读稿 → 声音导演稿 → 实际生成提示词”的流程。

1. **原文**保存全文和位置。
2. **朗读稿**保存原文片段、说话人、内容类型和用户明确修改后的朗读文字。
3. **声音导演稿**为既有片段增加表演建议，为用户选择的场景增加声音事件。它引用朗读稿，不再生成另一份可独立修改的台词。
4. **实际提示词**由程序将当前已采用的设置和准确正文组合，保存到生成记录，用于复查。

这里的“调教”是针对模型能力优化剧本表达和提示词，不是微调模型权重。新层次首先复用已有表演字段、角色档案和生成记录，不先建设复杂的导演系统。

## 2. 用户提供的指南如何采用

| 提供的建议 | 本项目采用方式 |
| --- | --- |
| Scene、Voice、Ambience、SFX、BGM、Acoustic 分类 | 作为项目写作约定，按需使用；不是官方强制标签或独立接口参数 |
| 具体声学词优于泛泛评价 | 把“悲伤”进一步写成能听见的表现，例如语速放缓、句尾收弱；保留有用的情绪词，不一概禁止 |
| 核心声音放开头 | 开头明确任务和主音源，便于理解；不声称位置有已验证的权重机制 |
| 按叙事先后写声音 | 显式说明先后、同时、持续及结束条件；不只依靠段落排列暗示时序 |
| 空间与设备描述 | 描述最终需要听到的效果；避免堆砌设备名和相互冲突的声学要求 |
| 100 ms 时间控制 | 官方说明主要针对角色对白；不能扩展为全部音乐、音效的硬性精度或本项目实测结果 |
| `@Audio` 参考控制 | 当前接入按文档使用 `@音频1` 等编号，程序按实际参考顺序填写，不直接照搬其他平台别名 |

官方介绍支持场景、角色表演及对白时间控制，但未在本次读取资料中规定上述五类标签必须使用。细粒度音效、环境与音乐控制仍列在继续发展方向中。[Seed 官方介绍](https://seed.bytedance.com/en/blog/from-speech-to-audio-creation-introducing-the-seed-audio-1-0-audio-creation-model)

官方接口接受自然语言提示；它的示例也使用中文。因此本项目先用中文写作，无需为了所谓标准格式强制翻译成英文。[火山接口文档](https://docs.volcengine.com/docs/DoubaoVoice/audio-generation-http?lang=zh)

“清晰录制后模拟电话滤波”是可以理解的制作要求；“高清”和“电话”同时出现不必然矛盾，应分清录音来源与最终声音效果。对用户列出的第三方指南，由于未提供具体页面，本次没有将其表述当作已核验的官方规则。

## 3. 七个写作维度

| 维度 | 回答的问题 | 示例 | 使用条件 |
| --- | --- | --- | --- |
| 朗读内容 | 确切说什么 | 保留已确认台词，不增加开场白 | 必须 |
| 角色与参考 | 谁在说 | 界面显示沈砚；请求写说话者 B，参考 `@音频2` | 必须；槽位及编号由本次映射确定 |
| 场景与意图 | 为什么这样说 | 怕门外的人听见，提醒同伴安静 | 有助表演时简写 |
| 逐句表演 | 怎么说、哪里变化 | 压低声音，“别”稍重，句尾短促 | 按片段填写 |
| 互动与时序 | 谁接谁、哪些声音重叠 | A 说完后 B 回答；不重叠 | 多人组或声音事件需要时 |
| 环境、音效、音乐 | 听到哪些额外声音 | 持续雨声；指定位置敲门两下 | 用户主动启用场景声音时 |
| 声学与主次 | 声音如何呈现 | 对白清楚靠前，环境声较轻 | 干声使用统一简短要求 |

不要求每句填满七项。普通旁白通常只需要正文、参考声音和简短表演要求。每条先突出一至三个最关键的表演意图，避免形容词相互争夺表达重点；这是本项目起步策略，需要通过样本调整。

### 3.1 角色长期特征与本句状态分开

- **角色稳定特征**：用户选定的参考资产、口音、基础声线。跨章复用。
- **本句状态**：压低声音、疲惫、兴奋、犹豫等。随场景变化，不反写角色永久属性。
- 有参考时，避免每句重新写一套矛盾的年龄、音高和音质描述。参考身份与表现要求能否解耦仍需听辨。
- 原文没有的年龄、口音、性格，只能作为待采用的声音设计建议，不能写成角色事实。

### 3.2 表演写成可听见的动作

| 过于笼统的指导 | 可供用户采用的具体指导 |
| --- | --- |
| 很伤心 | 前半句勉强平稳，后半句放缓，句尾轻微发颤，不放声哭喊 |
| 很生气 | 压着怒气，咬字较紧，强调“现在”，结尾收短 |
| 紧张 | 声音压低，开头稍犹豫，后半句加快但字音完整 |
| 很有气势 | 起句坚定，重点词清楚有力，避免全句持续喊叫 |

上述是候选表达，不是固定情绪词典；“愤怒”也可能表现为冷静低声。优先按上下文判断，没把握时采用中性表达并标记待确认。喘息、笑声、哭声等额外发声单独提出，不因情绪词自动加入。

### 3.3 忠实有声书与戏剧改编分开

“门外传来两下敲门声”在忠实有声书中仍由旁白朗读。场景模式可以建议叠加敲门音效，但不能用音效偷偷替换原句。“林夏说”也不能因为已有角色声音而自动删除。

用户明确删改的内容继续按主设计保存差异。自动将叙述改成对白、增加人物反应、删掉引述语属于改编，不在当前默认任务内。

### 3.4 建议、采用与过期

建议引用片段 ID 还不够。程序在发起分析时记录章级编辑修订、项目文本上下文修订、目标 ID 和原文出处；采用时重查两类修订及任务只读状态。章节内容修改，或从其他入口更新角色资料、别名、事实来源、章节叙事顺序，都使旧建议仅供查看，不能直接采用。上下文变化不自动让已确认音频失配或重跑，具体更新条件沿用主文档第 3.4、8.2 节。

默认逐条审阅并勾选草稿，最后一次“应用本轮选择”；勾选不改正式剧本，整批采用在一个事务内完成。仍保留明确的单条立即采用，但其余建议随后需要重新分析。任务进度与生成结果登记不算用户编辑，不使同批后续任务自行过期；不建设自动合并算法。

原文明示使用有效的文本块／区间引用；模型写一句“根据原文”不能代替出处。引用可定位也不代表推理正确。文本模型不得自行授权采用、猜新 ID 或修改程序记录的基准修订。

## 4. 给剧本整理模型使用的指令模板

本模板面向负责理解小说的文本模型，不能直接当作 Seed Audio 的音频生成输入。前提是程序已提供可定位的片段；原文分段与覆盖检查仍沿用主方案 v0.2.1 第 3 节。

```text
你是有声书声音导演，为 Seed Audio 1.0 整理表演建议。

输入包含：
- 带片段 ID 的已确认朗读稿及相邻原文上下文；
- 截至本章已知的角色资料、已绑定参考声音及已确认表演设置；
- 制作模式：逐条干声 / 用户选中的多人对戏组；
- 是否允许提出环境、音效、音乐建议。

任务：
1. 保留片段 ID、原有顺序、朗读正文和已确认角色。
2. 每条给出简短表演建议，说明情绪、发声方式或节奏中最必要的部分。
3. 标明依据：原文明示 / 上下文推断 / 创作建议。
4. 有依据的情绪变化写清发生在哪个词句；不能确定则不虚构变化。
5. 发现角色归属疑点时单独列为待确认项，不自行改绑。
6. 不补写人物台词，不删除叙述，不改变人称，不让角色朗读导演说明。
7. 默认为干声。身体动作只指导表演，不自动产生脚步、衣物等声音。
8. 只有允许场景建议时才提出额外声音；区分持续背景与一次性事件。
9. 声音事件引用已有片段 ID 和之前 / 期间 / 之后，不猜精确时间。
10. 默认保持原文顺序，不自动抢话、重叠、加入额外戏剧留白或固定时长要求。
    可提出有上下文依据的句内停顿建议，用户采用后才参与生成。
11. 不从后续章节补充角色事实，不覆盖用户已确认的表演设置。
12. 所有新建议先作为草稿，等待用户采用。

输出：
逐条建议：片段 ID | 表演建议 | 依据类别 | 有效原文引用或推断说明 | 待确认问题。
如允许场景建议，另列：声音类型 | 声音描述 | 对应片段与时机 | 依据及出处。
不要重复输出整份朗读正文，不生成或猜测参考音频编号。
```

软件接入时采用结构化返回承载这些字段，并校验 ID、出处及采用时的基准修订。展示表格只是人工讨论格式；无须为了这个提示词另造一份独立剧本数据。覆盖完整性由程序检查，表演合理性由用户判断。

依据类别只使用“原文明示／上下文推断／创作建议”三项。制作层面的保守默认归入创作建议，括号说明不是第四个枚举值。两类基准修订由程序附带保存，不让模型编造。

## 5. 从建议变为实际音频输入

用户采用建议后，程序按照当前生成单元组装提示词：制作任务 → 角色参考 → 必要情境 → 表演与时序 → 精确正文 → 可选声音设计。

- 只纳入本次生成单元的朗读内容，邻近台词作为理解上下文时不能混入朗读区。
- 界面姓名不作请求标签；单条用“说话者 A”，多人按首次出场次序分配槽位，保存“槽位 → 稳定角色 ID → 参考资产”映射。参考编号按实际资源顺序对应，排序改变时同步重建编号。正文里的原有人名照常朗读，不能替换成槽位；修改档案显示名不会改正文，也不会重写用户已采用的自由指导。
- 未采用的建议不进入请求；只有上下文里出现某个声音，不等于用户同意生成它。
- 干声与场景使用不同模板，不能一边要求无环境声，一边追加雨声和音乐。
- 必须把正文和表演要求合成同一实际 `text_prompt`。当前 Kunpo 的 `instructions` 是缺省回退字段，不能把正文放在 `input`、表演放在 `instructions` 后期待它们自动合并。
- 每个片段／生成单元保存有效模板版本，本次提示、参考映射、输出设置及该版本写入生成记录。普通改字和重跑沿用有效版本；用户明确应用新模板才升级。拆分继承父版本，合并／成组存在版本差异时明确统一，恢复旧版设置时展示并恢复对应模板；应用保留被引用的模板实现，不静默替换缺失模板。这里只约束应用可控的配置，不声称固定供应商内部变化。

当前路由支持最多三条参考音频，提示不超过 3000 字符，单次生成最长 120 秒。返回混合音频二进制，不能把提示中的模块名称理解成独立音轨。[Kunpo 接口说明](https://docs.ziy.cc/api-reference/seed-audio/)

提交时发现最终提示超限，阻断本次提交并提示用户按语义拆分生成单元；用户确认新的生成范围后再提交，不截断正文，不自动追加请求。提取阶段仍可提出分段建议；此规则不增加独立审批步骤。

基础首版界面仅编辑正文和表演指导；场景实验开放后才提供声音事件和场景指导。实际提示只读预览，避免出现“字段一份、手改提示另一份”的冲突。超出模板的普通自然语言需求写入对应指导字段，不能借此绕过模式范围。

编译前先处理冲突：干声模式与声音事件不能同时启用；确定的数值设置只保留一份实际值。角色常态和组级表演是默认，本条已确认表演是明确例外；不要同时要求“全程平静”与“此句突然喊出”。同一条中相互矛盾的指导交用户修改，不能自行覆盖。程序校验结构化冲突，文本模型可辅助指出语义冲突，但无法保证检出全部自由文字问题。

提交前沿用主文档第 8.1 节的范围校验。最终提示超限或参考不合法时不发送、不截断正文、不暗中增加请求；未采用建议不进入提示。参考未测试只是提醒，未确认角色或缺失参考则阻断。

## 6. 完整示例：同一段文字的三种制作方式

以下文字为本规范自拟示例，不是用户小说或已验证音频。

> 沈砚停在门口，压低了声音。“别出声。”门外传来两下敲门声。“是我。”林夏说。

### 6.1 忠实朗读稿及待采用建议

| ID | 角色 | 朗读内容 | 表演建议与依据 |
| --- | --- | --- | --- |
| S1 | 旁白 | 沈砚停在门口，压低了声音。 | 中性叙述，清楚交代动作；创作建议（制作层面的保守默认） |
| S2 | 沈砚 | “别出声。” | 压低声音；原文明示。短促、克制；上下文推断 |
| S3 | 旁白 | 门外传来两下敲门声。 | 清楚平稳，不模仿敲门；创作建议（制作层面的保守默认） |
| S4 | 林夏 | “是我。” | 简短自然，避免夸张；创作建议（制作层面的保守默认） |
| S5 | 旁白 | 林夏说。 | 自然收尾；创作建议（制作层面的保守默认） |

五条原始内容按顺序连接即可还原原文。引号是文本标点，不要求口述“引号”。本例不能凭空推断林夏恐惧、哭泣或带特定口音。

### 6.2 逐条干声：生成 S2 的实际提示示例

前提：用户已采用表演建议，当前请求只传沈砚的一条参考声音。界面显示沈砚，程序保存“说话者 A → 沈砚的稳定角色 ID → 当前参考资产”的映射。

```text
[任务]
生成一条中文角色对白，只朗读正文一次。说话者标签、参考编号、标题和说明不读出。

[角色]
说话者 A，声音身份参考 @音频1。

[表演]
压低声音，短促而克制，吐字清楚。不要增加喘息、笑声或额外台词。

[正文]
“别出声。”

[声音呈现]
清晰干声，无音乐、环境声和额外音效，无明显空间混响。
```

其他片段分别生成，统一 0.5 秒间隔由工作台合并时加入，不要求模型在每条末尾预留同样静音。句内自然节奏与应用的片段间间隔分别管理。

### 6.3 多人干声：先单独验证对戏价值

用户明确将 S1～S5 成组。程序映射为 A＝旁白、B＝沈砚、C＝林夏，参考顺序也为旁白、沈砚、林夏。等号右侧仅为界面解释与内部映射，以下请求标签使用槽位。

```text
[任务]
生成一段中文多人有声书干声，按正文顺序逐条朗读，每条只读一次。
说话者标签、参考编号、标题和说明不读出，不增加其他台词。

[角色与表演]
说话者 A 使用 @音频1 的声音身份，负责叙述，清晰平稳。
说话者 B 使用 @音频2 的声音身份，压低声音，短促而克制。
说话者 C 使用 @音频3 的声音身份，简短自然，不夸张表演。

[正文与顺序]
说话者 A：沈砚停在门口，压低了声音。
说话者 B：“别出声。”
说话者 A：门外传来两下敲门声。
说话者 C：“是我。”
说话者 A：林夏说。

[声音呈现]
清晰干声，无背景音乐、环境声或敲门等音效。
轮流说话，不重叠；保持自然句内节奏，不增加额外戏剧留白。
```

这一步只改变生成粒度，不增加声场元素。基础模式每条调用独立分配槽位和参考编号，不能直接复制组里的 `@音频2` 到只有一条参考的请求。组内参考、数值配置一致性要求及返工范围沿用主文档第 17.5 节。

### 6.4 多人场景：再单独验证声音事件

前提：用户主动创建对戏组，并采用“增加两次敲门音效”的建议。参考顺序为旁白、沈砚、林夏；叙述、原台词全部保留。

```text
[任务]
生成一段中文有声书场景。按正文顺序逐条朗读，每条只读一次。
说话者标签、参考编号、标题和表演、音效说明不要读出；不增加其他台词。

[角色]
说话者 A：声音身份参考 @音频1，叙述清晰平稳。
说话者 B：声音身份参考 @音频2，压低声音，短促而克制。
说话者 C：声音身份参考 @音频3，简短自然地回应，不夸张表演。

[正文与顺序]
说话者 A：沈砚停在门口，压低了声音。
说话者 B：“别出声。”
说话者 A：门外传来两下敲门声。
说话者 C：“是我。”
说话者 A：林夏说。

[声音事件]
说话者 A 读完第三条正文后，出现两下较轻的敲门声。
敲门声结束后，说话者 C 再读第四条正文。敲门声不遮盖台词。

[声音呈现]
人声清楚靠前，敲门声稍远。无背景音乐，不增加其他环境音。
各说话者轮流说话，不重叠，不故意拉长空白。
```

标题是帮助表达意图的项目约定，没有格式本身的效果保证。场景一次生成一个混合结果；改一句通常要重跑整组，不承诺独立更换敲门声或精确按句裁切。保留已有干声结果；若尚无干声，不因选择场景而偷偷增加另一轮付费生成。

事件在软件内锚定 S3、S4 及其相关修订，编译时才换成当前组内的第三／第四条；不能只保存“门外传来两下敲门声”这段文字再猜位置。同文重复、片段编辑、拆分或删除时按第 7 节复核。

## 7. 场景扩展的写法

只有用户启用对应声音后，才加到场景模板中；未启用的模块省略或明确为无。

| 模块 | 建议表达 | 需要避免 |
| --- | --- | --- |
| 持续环境 | 全段保持轻微窗外雨声；低于人声；结尾自然收住 | 只写“下雨的房间”，让模型自行决定雨声存在与否 |
| 一次性音效 | 在 S3 结束后敲门两下，结束后进入 S4 | 只列“敲门、脚步、雷声”，没有数量与时机 |
| 背景音乐 | 轻柔低音弦乐铺底，无歌声，对白出现时保持较轻 | “史诗、紧张、悲伤、轻快”同时堆叠 |
| 空间 | 角色对白带轻微小房间反射，旁白保持清晰近讲 | 要求所有声音同时完全干燥又有强烈大厅混响 |
| 时间 | 有剪辑需要时指定某句目标起点，并测量实际输出 | 普通小说每句强行填秒数、要求模型赶时长吞字 |

“低于人声”“自然收住”等是生成意图，不是可量测的混音参数。需要准确增益、淡入淡出或严格时长时，应评估后期处理；不能用提示词承诺分贝、采样级边界或独立轨道。

接话与抢话也应显式设计：只有原文或用户允许时才在对戏组中采用。若抢话会吞掉原文词句，需要用户决定是否接受改编，默认保留完整正文。没有真实对齐结果，场景播放只高亮整个组。

声音事件记录片段 ID、相关文本／角色／类型的基准修订或快照、相对时机和采用状态。锚点变化、排除、拆分、合并、退出单元或组顺序变化后标为待复核，不按文本相似度搬移。已采用事件失效时，先修正、重新确认或移除再发送场景请求；只有未采用建议时无需阻断。单纯改显示名不改变锚点。解除分组时显示哪些事件退出当前编排，不假装单条干声保留了混合音效。

## 8. 最小验证：确定哪些写法有效

本次只设计实验，不执行生成。选择同一段已确认正文与相同参考声音，分三步控制变量：

1. 逐条干声的简单情绪标签与具体表演指导对比，检查表演收益。
2. 使用同一份已采用指导，比较逐条干声与成组干声，检查互动、身份和整组返工代价。记录逐条的外加间隔与组内自然停顿，不能把停顿差异全归因于表演提示。
3. 在同一组上比较干声与加入已采用事件的场景版，检查音效收益和遮盖问题。

不能把不同制作目标直接当作同一质量排名，也不一次改变参考、台词、表演和声场后把改进全归于模板。

检查并记录：

1. 台词完整性：漏读、重复、增词，是否读出了标签或指导。
2. 角色正确性：说话人是否匹配，参考身份是否稳定。
3. 表演：要求的变化是否听得见，是否过度表演。
4. 声音事件：数量、先后是否正确，是否遮盖台词。
5. 可制作性：等待时间、返工次数，修改一句需要重做多少内容。

同一条件必要时重复生成，观察波动；不要靠一个出色样例断言模板稳定。保留实际输入与音频，按用户听辨结果逐步修订规则。生成音频的文字核对仍需试听或另行转写比对；剧本原文覆盖检查不能证明音频逐字正确。

## 9. 纳入工作台的最小改动

首版先落实“基于片段提出表演建议 → 用户采用 → 正文与指导组合发送 → 记录实际提示”。角色声音、逐条返工、状态恢复沿用现有设计。

对戏组、环境、音效和音乐属于可选扩展，按模型能力补充文档的小样计划验证后交付。基础列表不增加七个必填输入框，也不自动把整章变成带音乐的广播剧。

声音创建、多人干声及场景分别按主文档第 1.3 节安排；检查状态、旧版恢复、素材资格和任务恢复统一遵循主文档，提示规范不另造一套状态规则。编译可检查正文、标签、参考和结构一致性，不能保证模型听感、漏读或抢话效果。
