## 1. 产品定位与范围

将小说逐章制作成多角色有声书。AI 建议原文分段、说话人和表演方式，用户确认角色与音色，生成后对照剧本试听、逐条返工，最后导出章节。

核心能力是跨章角色延续、正文完整、声音可控、单条可返工、制作进度可恢复。AI 不自动改写小说，不覆盖用户确认的角色绑定。

### 1.1 第一版包含

| 模块 | 能力 |
| --- | --- |
| 项目与章节 | 创建、重命名项目；导入、排序和打开章节；持久保存 |
| 文本导入 | UTF-8 TXT、Markdown、粘贴文本；一次制作一个章节 |
| 剧本提取 | 以原文为依据标注旁白、对白、心理独白、角色与表演建议；检查覆盖完整性 |
| 校对 | 原文对照，修正说话人、朗读文本、音色和表演要求；拆分及合并相邻片段 |
| 角色档案 | 项目内姓名、别名、来源、简介、性别信息、默认音色；跨章复用 |
| 音色库 | 参考音频上传、命名、试听、可选生成测试样音；跨项目复用 |
| 生成 | 整章排队生成、补做缺失或待更新项、单条重跑、故障与恢复提示 |
| 试听 | 单条试听、同源整章试听、暂停与续播、高亮和跟随滚动 |
| 检查 | 待检查／已通过／需返工；允许整章统一确认，不强制逐句采用 |
| 导出 | 从当前试听母版生成 WAV、MP3；旧成品继续可下载但标明版本已过期 |
| 本地管理 | 明确启动与停止方式、数据目录、数据库和音频共同备份恢复 |

### 1.2 第一版不包含

整本书无人值守制作、多人实时协作、背景音乐与多轨编辑、自动小说改编、EPUB／PDF／OCR、字级字幕、口型同步、自训模型、自动发行、无限版本历史。这些是基础首版的范围选择，不代表 Seed Audio 只具备逐句干声能力；声音场景等扩展见第 17 节。

以中文小说为验收对象。非破坏性增益、单边界间隔覆盖、自动静音处理先根据样本决定，不默认扩大首版范围。若只需改音量或静音长度，不应引导用户付费重新生成。

## 2. 核心对象与完整流程

| 对象 | 定义 |
| --- | --- |
| 项目 | 一本小说，包含共享角色档案和多个章节 |
| 章节原文 | 上传源文件与确认后的解析正文；区间定位始终对应明确的正文修订号 |
| 角色 | 项目内稳定身份，名称可变；旁白作为特殊角色管理 |
| 音色档案 | 用户命名的参考声音资产，不等于已训练永久音色 ID |
| 配音片段 | 独立校对、生成和返工的最小单元，可为短句或短段落 |
| 生成记录 | 一次实际音频生成尝试及其输入、文件、结果状态 |
| 当前音频 | 当前被选用的生成结果，可能待检查或已与新设置不匹配 |
| 章节编排 | 实际使用的音频记录、顺序、间隔、帧数及处理配置 |
| 试听母版 | 根据章节编排生成的可缓存音频，供总播放器与最终导出共用 |

标准流程：

1. 创建项目，上传或粘贴一章，确认标题与解析正文。
2. AI 标注原文，程序检查分段覆盖、顺序与引用有效性。
3. 处理待确认角色、别名、心理独白和说话人归属。
4. 展示本章角色，为未绑定角色选择音色，自动补齐本章符合条件的片段。
5. 检查剧本与生成范围，开始按条生成。
6. 新结果技术成功后自动成为当前音频，标记待检查。
7. 准备试听母版，用户连续试听、标记问题、修改和单条重跑。
8. 新结果替换后重建所需母版；用户检查通过，可逐条或整章确认。
9. 点击“确认检查并导出”或对已确认章节直接导出，从同一母版生成章节文件。

生成、重跑、母版构建和导出期间本章制作数据只读。其他章节可以编辑。只读由服务端执行，不能通过其他标签页绕过。

## 3. 小说提取与正文保真

### 3.1 程序保存正文，模型负责标注

不让模型重写整章再以输出代替原文。程序先保存源文件，建立用户确认的解析正文，分配文本块 ID 和确定的边界；模型返回文本块／区间引用、角色、内容类型和表演建议。初始朗读文本由程序从正文提取。

第一版采用保守导入：统一换行后预览；Markdown 默认按文本导入，不自动删除代码、链接、标题等可能属于正文的内容。用户明确不朗读的标题、分隔符等保存为排除区间；不得根据模型猜测删除“他说”等叙述。

区间使用左闭右开边界，以服务端定义的 Unicode 码点计数，正文修订号必须匹配。优先让模型选择程序给出的块 ID 和边界标记，不依赖模型自行数长文本字符。新增内部切点必须能精确定位；引用歧义、越界或无效时展示对应原文，重新标注或由用户定位，不模糊匹配后悄悄接受。

应用在接受提取结果时做普通输入校验：

- 每个区间均位于对应正文内，起止有效。
- 按原文顺序排列，不能出现重叠和重复引用。
- 应朗读的非空白内容全部被覆盖，任何未覆盖文字都可定位。
- 排除内容必须来自已明确记录的导入处理或用户选择。
- 分块的上下文可以重叠，但每块只有自己的输出负责区间，不能把参考上下文重复输出。

有问题时保留有效草稿和原文，指出具体缺口，不接受成“完整剧本”。这些校验保证原文保留情况，不能证明说话人、情绪或生成音频的逐字正确性。

### 3.2 上下文和人工修改

优先在模型可承载范围内理解完整章节；分块时携带相邻上下文及本章可用角色信息。未确定的无署名对话、指代和别名归属显示待确认，不把猜测写成已确认。

初始文本直接来自原文；用户之后修改朗读文本时保存原文引用和差异。用户改字、删去朗读内容属于显式校对，不应被当作模型遗漏；结构覆盖检查与用户修改提示分开展示。整章原文更换后产生新的解析草稿，不能让旧坐标继续指向新正文。

拆分片段保留对应区间映射；合并只允许相邻、同角色、同类型片段，并重新确认表演设置。新片段重新生成，不猜测旧音频如何裁切。已有音频的旧片段先保留为被替代记录，不在操作中删除文件。

重新提取只生成待采用草稿；接受时检查章节修订号，若用户期间编辑过章节则提示冲突，不覆盖新修改。

### 3.3 心理描写的声音归属

- 明确的直接心理独白，如“我不能再等了”，建议使用该角色声音，类型标记为心理独白。
- 第三人称心理叙述，如“他担心自己会迟到”，默认归旁白，不自动变成角色第一人称。
- 无法区分时标记待确认，允许用户选择角色或旁白；不自动改写人称。

### 3.4 面向 Seed Audio 的声音导演稿

在忠实朗读稿上增加模型适配的表演建议，按“具体片段、表演要求、依据、待确认问题”组织；区分原文明示、上下文推断和创作建议。建议引用既有片段 ID，不复制出另一份独立台词，不覆盖已确认角色和表演设置。用户采用后才进入生成请求。

程序组合准确正文、角色参考和已采用指导，提供实际提示的只读预览并保存到生成记录。默认仍为逐条干声；环境、音效、音乐和互动时序只在相应扩展被主动选择时加入。详见 [专用剧本与提示词写作规范](./Seed-Audio-1.0专用剧本与提示词写作规范.md)。

## 4. 角色、别名与跨章信息

每个角色有稳定 ID、姓名、别名、简介、性别及其确认状态、默认音色。无法从原文判断的性别显示未知。旁白也需要配置音色。

不额外建设长期记忆系统。用普通角色记录、信息来源和本章角色摘要延续身份：

- 简介、性别、别名等事实附来源章节及原文依据。
- 本章展示和提取只使用截至本章叙事顺序可知的信息，并保存本章确认的简介；后章分析不重写旧章简介。
- 用户补充的信息要标明适用起始章节，不明时默认从当前章使用。
- 全局默认音色可以跨章沿用，身份事实的未来信息不能借此进入旧章提示词。
- 章节重排后刷新可用信息范围、提示复核，不自动重做既有音频。

同名不等于同角色；别名可对应多个候选，不设项目内姓名唯一规则。用户确认新别名后才保存正式关系。

误建重复角色时提供“将所选片段改绑到已有角色”，显示范围与音色影响；全部引用已处理后可以归档空角色。误合并时创建独立角色并将选定片段重新绑定。首版不做不可逆的全项目自动角色合并；处于任务锁定中的章节不能批量改绑。

## 5. 音色库与绑定规则

### 5.1 建立音色档案

上传 WAV／MP3 → 校验可解码性、大小和时长 → 命名与试听 → 保存。生成新文本测试样音由用户主动点击，可能产生费用；未做样音检查不阻止保存，显示“未验证”。

按项目已有模型文档，单条参考最长 30 秒、最大 10 MB；实施时复核接口约定。超限明确报错，不静默截取。素材复制到应用持久目录，不依赖上传者原文件位置。

第一版每个音色使用一条参考音频；用户每次生成时复用它。参考音频已能送入模型不等于长期声音一致性通过验收。永久供应商音色 ID 仅在实际取得并确认可用后使用。

音色库独立于项目，同一用户可跨项目复用；片段的默认或覆盖音色必须来自音色库。更换参考素材创建新档案，不能让已有绑定静默换声。

### 5.2 绑定与改绑行为

| 操作 | 明确行为 |
| --- | --- |
| 首次绑定角色音色 | 设置角色默认值；自动补齐当前章该角色“无音色且没有单条覆盖”的已有片段；后续新片段沿用；不改其他已有章节 |
| 当前章已有明确音色 | 首次绑定也不覆盖，显示其实际绑定 |
| 单条选择音色 | 标记为本条指定，不改变角色默认值 |
| 恢复使用角色默认 | 将角色当前默认值复制到本条，来源改为角色默认；无默认值则本条待配置 |
| 修改角色默认音色 | 默认仅影响后续新片段；已有片段保留原来确定的选择 |
| 应用新默认音色到本章 | 显示受影响条目，用户执行后更新；默认排除本条指定；仅实际请求变化的音频需要重跑 |
| 角色 A 改为 B，音色来自角色默认 | 本条改为 B 当前默认音色；B 未配置时清空为待配置，不能继续沿用 A 的默认声音 |
| 角色 A 改为 B，音色为本条指定 | 保留指定音色并显示待核对提示；用户确认保留或切到 B 默认 |

片段保存实际音色 ID 和来源，不在播放或任务执行时动态读取角色默认值。角色默认修改可用于未来片段，但“应用到本章”等影响锁定章节的操作由服务端拒绝。

### 5.3 归档、停止使用和删除

- 归档：不供新选择，已有引用仍可试听、生成。
- 停止未来生成：保留既有产物，但拒绝任何新的生成请求；已发出的请求无法保证取消。
- 删除参考素材：单独操作，展示受影响章节，删除后相关片段不能再使用该参考重跑；已有成品是否一并删除必须由用户明确选择。

素材使用授权、向所选服务发送的许可，以及供应商数据保留和商用条件，在正式上线或使用前按真实条款核实并记录范围。本稿不做法律结论，也不把一次技术调用成功当作授权证明。

## 6. 工作台界面

- 左侧：项目、章节列表和状态，音色库与设置入口。
- 中间：剧本列表，展示序号、角色、音色及来源、表演要求、台词、状态、试听、检查与重跑。
- 右侧：当前片段编辑、原文及前后文、角色详情；窄屏使用抽屉。
- 顶部：章节标题、待确认／待更新／待检查数量、生成进度及当前主要操作。
- 底部：总播放器、当前位置、播放／暂停、跟随开关与返回当前条。

长台词换行，不因频繁更新进度造成行高抖动。状态同时有文字与图标，主要操作支持键盘与明确焦点。

情绪采用常用预设加自由描述，不提供未经验证的精确强度或准确率。将该编辑项完整命名为“表演指导”，可表达发声方式、身体状态、情绪变化、节奏与声音动作，默认仍以简洁摘要展示；具体设计见第 17 节。表演提示建议保持可执行，例如“压低声音、警惕、短暂停顿”。

筛选支持全部、待确认、待生成／更新、失败、待检查、需返工。筛选只改变列表，不改变章节播放顺序；当前条隐藏时显示返回入口。

Beautiful UI 参考任务状态与列表表达；React Bits 仅用于必要反馈，不默认采购或引入组件。第一版没有 3D 场景，不引入 Three.js。

## 7. 音频状态、用户检查与修改影响

### 7.1 三个独立维度

| 维度 | 状态示例 | 含义 |
| --- | --- | --- |
| 最新生成任务 | 无任务、排队、生成中、成功、失败、结果不明、未提交已停止 | 描述这次尝试，不能覆盖历史成功结果 |
| 当前音频有效性 | 缺失、匹配、待更新、文件损坏／缺失 | 描述当前音频是否可用及是否匹配当前实际请求设置 |
| 用户检查 | 待检查、已通过、需返工 | 绑定具体生成记录；播放结束本身不等于检查通过 |

新音频技术成功后自动成为当前音频，检查状态为待检查。继续试听不要求先通过；最终确认导出需要没有待更新、缺失或需返工项。

用户可以单条标记通过，也可以整章检查后统一确认。导出按钮可执行“确认检查并导出”，将当前匹配版本的待检查项一次确认，不要求每句多点一次“采用”。已标记需返工的条目不能被整章确认静默清除，必须明确处理。

### 7.2 重跑失败的组合规则

| 情况 | 结果 |
| --- | --- |
| 未改变设置，尝试再生成一次但失败 | 当前音频仍匹配；保留原检查状态，可继续使用；若用户先前标记需返工，则仍需处理 |
| 修改音色、正文等后重跑失败 | 旧音频待更新，只能明确标注的单条旧版试听；不能进入当前母版或正式导出 |
| 新生成成功 | 自动替换当前结果，标记待检查，旧母版需更新 |
| 技术成功但用户听出问题 | 标记需返工，允许继续试听定位；正式导出前处理 |

### 7.3 有限保留与恢复

每条保留当前音频、直接上一版、最近一次已确认通过的音频三个引用；它们可以指向同一记录。连续多次不满意的重跑不得覆盖最近已通过版本。

恢复操作一并恢复该记录对应的片段生成设置；如果恢复的是已确认通过版本，可恢复其检查通过状态，章节母版仍需更新。恢复不修改角色全局默认值。设置引用对象被停止使用时可以播放已有结果，但不允许据此发起新生成。

被旧导出、备份或结构编辑保留的记录不能随意删除。不做每次成功后自动清理文件；磁盘清理作为显式维护操作，仅删除无引用素材，避免引入复杂自动回收机制。

### 7.4 修改影响表

| 修改 | 重新生成 | 重建母版／导出 | 检查影响 |
| --- | --- | --- | --- |
| 正文、实际参考音色、表演提示、模型、有效语音参数 | 是 | 新音频产生后重建；旧版立即不再代表当前配置 | 旧通过记录保留，新结果待检查 |
| 改角色归属 | 仅当实际请求改变时 | 依实际音频变化决定 | 归属与音色须核对；即使未换声也重新检查本条 |
| 只改角色显示名、音色名称、说明 | 否，前提是不进入实际请求 | 音频无需重建，界面文字刷新 | 通常不撤销 |
| 片段顺序、章节间隔 | 否 | 是 | 单条通过保留，章节编排需再确认 |
| 未来若增加增益、边界静音覆盖等后期处理 | 否 | 是 | 受影响听感及章节编排需再确认 |
| 拆分、合并片段 | 新片段需要 | 是 | 新片段待检查，旧记录保留 |
| 更改未来使用的角色默认音色 | 不影响已有片段 | 不影响已有章节 | 不撤销已有检查 |

决定依据是规范化后的实际生成配置，不是界面字段名称。角色显示名默认不写入配音请求，使用稳定角色引用；简介不会自动加入请求，若采纳为表演提示则按实际请求变化处理。修改后又改回完全相同的配置，可直接恢复匹配关系，不强制额外付费生成。

## 8. 任务执行、只读与故障恢复

### 8.1 批量与进度

按片段分别生成，服务端单工作队列顺序处理。已完成／总条数、当前条、失败数和已耗时取自真实任务状态，不伪造模型内部进度或精确剩余时间。

“补做”仅提交缺失、待更新或用户选定的需返工片段，不因最新尝试失败就重复生成所有已匹配音频。执行前固定本次目标片段及实际输入，不在排队后偷偷采用新默认值。

### 8.2 服务端一致性

- 在同一数据库事务中检查章节修订号、任务状态并创建任务；一个章节同时最多有一个活动制作任务。
- 本章任务从排队起只读，所有写入口都检查，包括片段编辑、角色改绑、批量应用音色、间隔、删除和替换原文。
- 其他章节可编辑；仅修改未来默认值等不会改变当前任务输入的全局操作可继续。
- 普通页面保存带预期修订号。另一标签页已经修改时返回冲突，要求刷新或重新应用，不能最后写入者静默覆盖。
- 同一次点击命令生成一个本地命令 ID；网络重发和重复请求复用 ID，由唯一约束返回已有任务。连续双击期间前端保持同一命令，服务端章节活动任务约束进一步阻止并发重复。
- 用户在前次结束后明确再次重跑才使用新命令 ID。这是本地去重，不是供应商幂等承诺。

用普通 ID、版本号、唯一约束和事务实现，不新增内容哈希、冻结合同或复杂消息中间件。

### 8.3 音频落盘与启动对账

1. 先持久化任务、尝试 ID 与本次实际输入，再提交远端请求。
2. 在任务专属路径写临时文件，不写入当前音频路径。
3. 完整接收后检查内容类型、可解码性与时长，持久保存并在同一文件系统原子改名为该尝试的结果文件。
4. 在数据库事务中登记文件属性和生成结果，更新当前／上一版引用及章节编排状态。
5. 启动时按任务 ID 对账：存在完整有效结果但数据库未完成登记时，补登记而不是重新调用模型；不完整文件保留为故障证据，不当作成功音频。

若任务已经被用户放弃或后续修改替代，找回的结果只保存为该尝试产物，不自动覆盖当前片段。更新当前引用前再次检查任务与章节修订是否仍适用。

### 8.4 停止、失败与结果不明

“停止后续生成”停止提交剩余请求，已发出的请求继续等待其结果，不能承诺远端取消或不收费。尚未提交的片段恢复待生成。

单条明确失败可继续下一条；鉴权、余额、持续限流等共享问题暂停队列。请求超时、连接中断或进程崩溃造成结果不明时暂停，不自动再次付费请求。

进程内仍有请求在等待时保持活动任务。确认无法取得响应或服务重启后，将尝试标记结果不明并结束活动任务，解锁编辑；显示“可能已生成或计费”。用户可以明确再次提交，或恢复并继续使用已有匹配结果。迟到结果不得越过修订检查自动替换。

页面刷新和关闭不取消服务端任务。重新进入时读取数据库状态；不以浏览器是否还在等待判定任务已经失败。

## 9. 试听、断点与跟随

### 9.1 单条与整章

单条试听播放当前音频；过期音频仅在明确“试听旧版”操作下播放。单条与整章互斥，任意一种开始前停止另一种。

整章播放要求所有片段已有匹配、可解码音频，无活动生成任务。可以包含待检查或需返工条目，因为连续试听用于发现问题；不能包含缺失或待更新音频。未满足时允许单条检查，列明尚未就绪条目，不静默跳过。

第一次总播放及重跑之后可能显示“正在准备整章试听”；准备完成后才启用播放，不自动出声。总播放器使用第 10 节母版，不逐行用计时器拼接播放。

### 9.2 断点规则

- 普通暂停／继续保留母版内时间，间隔内暂停也保留其位置。
- 开始重跑时停止播放，记录稳定片段 ID。重跑后不沿用旧母版的绝对秒数。
- 新母版可用后点击继续，从原暂停片段的开头播放；若暂停位于两条之间的插入静音，将下一条视为断点条。
- 即使重跑的条目在断点之前或之后，也按记录的断点条继续；用户可单独试听重跑条目。
- 无断点时保持停止。断点片段被拆分、合并或移除时不猜测续播位置，提示重新选择起点。
- 重跑期间禁止播放；失败后若旧结果仍匹配，可继续使用原母版，否则只允许明确的旧版单条试听，待重新生成或恢复设置后再准备整章。

### 9.3 高亮与手动浏览

根据母版的实际时间映射高亮，不使用预计生成时长。插入静音期间保持上一条高亮并显示过渡状态，到下一条真实起点再切换。

开启跟随时，当前条滚动到列表中部附近。用户主动滚动暂停跟随；点击“回到当前播放”恢复，不反复抢走滚动位置。筛选隐藏当前条时保留播放器中的定位提示。

## 10. 同源编排、试听母版与导出

### 10.1 一份编排记录

每次准备章节音频时保存所用生成记录 ID、片段 ID 与顺序、统一后的采样率／声道、各段采样帧数、间隔帧数和后期处理配置。起止帧由实际解码结果计算，单一时间映射同时供母版和高亮使用。

首版优先采用已验证路径对应的 WAV 48 kHz 作为内部母版目标，声道数实施时统一；所有输入先转换到母版规格。间隔秒数按采样率四舍五入为整数帧，试听与导出使用相同结果。

编排使用普通修订号关联母版，不引入内容哈希缓存。音频记录、顺序、间隔或处理配置变化即生成新编排修订；仅显示名称变化无需重建音频。

### 10.2 母版构建与缓存

由服务端从该编排构建母版，总播放器播放同一文件并按映射定位。母版完成后验证可解码及总帧数与编排一致，再将其设为当前可用母版。

任务期间本章只读；发布母版引用前仍检查编排修订，过时构建结果保留为旧产物，不能替换新编排。现有母版对应旧配置时禁用其作为当前整章试听，清楚展示准备或待更新状态。

新母版仅做本地音频处理，不调用模型。相同编排重复播放或导出复用已有母版。旧母版和旧导出可以保留，但不能通过“当前导出”入口误领。

### 10.3 间隔

新章节默认额外插入 0.5 秒静音。设置页调整新章节默认值，当前章设置修改只影响本章。值应为有限非负数，第一版界面提供 0～10 秒范围并显示单位。

只在相邻片段之间插入静音，不给最后一条额外加尾间隔。生成音频自身首尾停顿保留，不默认强裁。超出此基础需求的单边界微调暂缓，先听样本判断必要性。

### 10.4 检查确认与正式导出

技术可用和用户检查分开：准备母版不要求逐条已通过，正式导出要求所有当前片段匹配、无需返工项，并由用户确认当前章节编排。

导出时显示仍待检查的条数，允许用户以“确认检查并导出”统一确认当前版本。普通播放结束不自动代替用户确认，不设置必须播放满多少秒的额外门槛。

章节确认关联当前编排修订。单条替换、顺序、间隔或处理变化后章节确认需要更新；未受影响片段的检查通过记录保留。最终 WAV 使用当前母版，MP3 从它转码。MP3 编码延迟等需在实际播放器验证，不承诺与 PCM 逐字节一致。

文件完整保存并验证后才更新导出记录。失败保留之前导出。旧文件下载标注制作版本和“非当前结果”，合并与转码不产生模型费用。

## 11. 模型接入与能力边界

文本模型负责原文标注、角色匹配和表演建议，具体服务待选。音频优先复用 Kunpo `seed-audio-1.0` 的已有调用路径。后端适配实际 API，不把应用内字段原样发送给供应商。

以下原先依据项目模型核验文档；本次后续已在线读取 Kunpo 和原厂接口页面，所列接入边界仍有文档依据，但没有新增真实调用。更广的模型创作能力及其设计影响见第 17 节：

- 端点 `/v1/audio/speech`，优先使用 `text_prompt + references + audio_config`。
- 表演要求写入自然语言提示词，没有据此假设独立可用的 `emotion` 参数。
- 音色使用参考音频或确认可用的音色 ID；兼容字段 `voice`、`speed` 不作为有效设置。
- 文档记录原生提示词最多 3000 字符、单次输出最长 120 秒；同时检查正文加说明的总长度，并按语义分段留余量。不能仅靠字数保证输出时长。
- 返回音频二进制；本地测时，不依赖字幕、账单或时长 JSON。
- 不承诺实时增量播放、远端取消、供应商请求幂等或确定性重现。
- 参考音频可提交、音频可解码，均不等于逐字正确、音色稳定和情绪合格。

请求保存实际参考素材 ID、正文、表演提示、模型与数值配置。提示词明确只朗读正文，不读说明，不添音乐与环境音；角色显示名等纯界面信息不混入。模板调整或模型默认变化不静默影响旧片段，用户明确应用后再按请求变化判断是否重跑。

## 12. 最小数据与本地实现

### 12.1 记录结构

| 对象 | 最少需要保存 |
| --- | --- |
| 项目 | ID、名称、时间 |
| 章节 | 项目、叙事顺序、标题、源文件、解析正文及修订号、间隔、编辑修订号 |
| 角色 | 稳定 ID、默认音色、姓名／别名／事实及来源章节、归档状态 |
| 本章角色信息 | 本章角色关联、确认的简介与事实引用 |
| 音色 | 参考文件及属性、名称、测试样音、未验证／已检查提示、使用状态 |
| 片段 | 原文修订及区间、顺序、角色、类型、朗读文本、音色与来源、表演和实际生成配置 |
| 生成命令与尝试 | 命令 ID、片段、输入配置、任务阶段、错误、文件路径与实际音频属性 |
| 音频选择与检查 | 当前、上一版、最近通过的记录引用；对应检查状态；当前匹配性可由实际配置比较得出 |
| 编排与母版 | 修订号、音频记录与顺序、帧数、间隔、处理配置、时间映射、母版文件 |
| 章节确认与导出 | 确认的编排修订、导出文件与格式、完成状态 |

事务处理引用切换和任务状态；文件通过第 8 节对账弥补文件系统与数据库不能共用事务的问题。普通版本号和输入比较足够，不新增哈希、复杂记忆系统或无限历史。

### 12.2 推荐架构

- 前端 React + TypeScript；浏览器原生音频播放与定位。
- 一个后端负责 API、持久任务和音频处理，语言在实施时确定，不拆多套服务。
- 单实例 SQLite 保存元数据，普通文件目录保存参考、结果和导出。
- FFmpeg／FFprobe 完成验证、测时、统一格式和合并。
- 单队列、单工作进程先跑通闭环；依据实测再调整吞吐，不引入独立队列平台。

### 12.3 本地生命周期与备份

首版按本地 Web 工作台实施，提供一个明确启动入口，启动服务后打开浏览器；默认只监听本机回环地址。浏览器关闭不停止服务，终端退出或电脑关机可能中断工作，需要在界面说明并提供运行状态。

提供“停止后续任务并关闭服务”：有活动请求时先等待或明确提示中断可能造成结果不明，不伪装为远端取消。崩溃恢复按第 8 节执行。

建议将数据统一放在可配置的持久目录，默认项目下 `data/`，包含数据库、原文、参考声音、生成结果、母版与导出。构建输出不能覆盖该目录；版本控制排除数据和凭据，路径以数据根目录的相对路径记录，便于迁移。

首版可用维护命令完成备份恢复，不必先做管理界面：

1. 停止新任务，等待活动任务结束；结果不明则先保存该状态。
2. 停止服务、正常关闭数据库，复制整个数据目录到带日期的独立备份目录。
3. 检查数据库可读及被引用音频存在，记录缺失文件，不宣称不完整备份成功。
4. 恢复到新的数据目录，验证后再切换服务；不覆盖唯一现存数据。
5. 实际打开恢复项目并播放样本，才算恢复验证完成。凭据独立配置，不混入普通备份。

公司在线版的发布、统一登录与账号隔离在部署阶段落实；若变成多人服务，所有项目、音色和文件访问必须按登录身份授权，不能共用默认用户。

### 12.4 基础保护

密钥只放服务端，不下发或记录到普通日志。上传验证大小、格式及实际可读取性；用户文件名不直接作为系统路径。原文和模型输出都是不可信数据，不作为执行指令。涉及文本或音频发送给服务时在对应生成操作说明用途。

失败不清除已有项目内容；删除和共享素材操作明确影响范围。生成费用仅有估算时标明估算，不假装实际账单。正式上线前复核供应商适用条款，保留未验证状态，不添加每句重复弹窗。

## 13. 验收用例

以下 30 条为本稿整理的可执行场景，不是外部审核附件的逐字转录。实现后记录输入、操作、实际结果与证据；目前全部未执行。

| 编号 | 场景／操作 | 预期结果 |
| --- | --- | --- |
| A01 | 导入包含重复句、引号、表情与 Markdown 标记的章节 | 源文保存、导入预览可核对，默认无静默删文，区间计数一致 |
| A02 | 模型返回漏字、重叠、越界或错误顺序 | 精确指出区间问题，拒绝接受为完整剧本，保留可修正草稿 |
| A03 | 长章分块，边界前后存在重复句 | 上下文不重复输出；同文不同位置可区分，最终覆盖一次 |
| A04 | 用户改字、删朗读内容、拆分和合并 | 原文引用仍可查，显式修改可见；新片段不误用旧音频 |
| A05 | 连续无署名对话、直接独白与第三人称心理叙述 | 不确定归属待确认；心理叙述默认旁白，无自动改人称 |

| A09 | 修改角色默认后应用到本章 | 未来新片段采用新默认；旧章不变；本章应用范围可见，覆盖项默认保留 |
| A10 | 两名角色重名或被误合并 | 不按名称自动合并；可选择片段改绑并修正，锁定章节不被绕过修改 |
| A11 | 先做后章再回头做前章 | 前章简介与提示不出现后章新增事实，用户确认的旧摘要不被改写 |
| A12 | 超限、损坏、移动原文件、归档或停止使用的参考音频 | 超限损坏明确报错；应用副本可用；归档可供旧引用重做，停止使用拒绝新生成 |
| A13 | 生成成功且可解码，但未人工检查 | 自动设为当前、标记待检查，不自动认定声音质量通过 |
| A14 | 不改设置重跑失败；换音色后重跑失败 | 前者保留匹配性与检查状态；后者只允许旧版单条试听，不混入当前成品 |
| A15 | 先确认好版本，再连续重跑三次 | 最近已通过版本仍可恢复，恢复对应设置，不更改角色默认值 |
| A16 | 只改名称、改音色、改间隔、改回旧设置 | 分别无需重跑、需重跑、只重建母版、可恢复配置匹配；不产生无关付费调用 |
| A17 | 双击生成及网络重发同一命令 | 返回同一任务，不重复远端提交；明确再重跑可以创建新任务 |
| A18 | 两标签页并发保存，生成时从另一入口改绑或删章 | 过期保存冲突；锁定写入被服务端拒绝，其他章节仍可编辑 |
| A19 | 音频已完整落盘、数据库登记前模拟退出 | 重启对账找回并验证产物，不再次请求模型；不适用的结果不覆盖当前设置 |
| A20 | 请求超时、服务中断、刷新或关闭网页 | 超时／中断不盲目重试；刷新可恢复状态；只关闭网页不取消后端任务 |
| A21 | 停止后续任务，或出现鉴权／余额错误 | 未提交项停止；已发送项状态明确；共享问题暂停，不反复错误请求 |
| A22 | 普通暂停、静音中暂停、重跑前后时长变化 | 普通续播保留时间；重跑按稳定片段重新定位，静音断点归下一条，不自动出声 |
| A23 | 单条试听切整章，播放时手动滚动和筛选 | 不重叠播放、不抢滚动；高亮和返回当前条正确，筛选不改变播放顺序 |
| A24 | 全部音频匹配但未检查；存在缺失或待更新条 | 前者可准备母版并试听；后者提示未就绪，不静默跳过或混用旧音频 |
| A25 | 初次总播放、同编排再次播放、重跑一条 | 首次真实准备；再次复用母版；重跑后旧母版失效，新版映射对应新时长 |
| A26 | 设置 0、0.5 秒及非法间隔，导出 WAV／MP3 | 合法值按统一帧数合并、末尾无额外间隔；非法值拒绝；两个格式内容顺序一致且可播放 |
| A27 | 待检查统一确认，存在需返工项，之后再换一条 | 允许整章确认；不能静默清掉需返工；换条后章节确认更新，其余单条通过保留 |
| A28 | 导出中失败，或旧构建结果迟到 | 旧导出可下载且版本清楚；过时构建不成为当前母版，失败不破坏原文件 |
| A29 | 停服备份并恢复到新目录 | 数据库及被引用素材完整，项目可打开、样本可播放，原数据未被覆盖 |
| A30 | 完成两段跨章多角色真实样本及一次单条返工 | 保存从原文到成品的记录，人工评估文字、声音身份和表演，记录返工次数、等待时间及费用口径 |

母版技术检查使用实际采样帧数；听感、角色和表演判断采用人工记录，不用“请求成功”或播放进度替代。MP3 播放兼容性和时间映射以目标浏览器实测为准。

## 14. 实施顺序与阶段交付

1. **声音能力验证**：用旁白加至少两名角色、短对白／长段落、隐式对话及不同表演要求的小样，跨两个章节片段复用音色。生成前写清评判方式，记录漏读增词、身份漂移、表演匹配、延迟与返工；本设计请求不自动执行付费调用。
2. **手工片段最小闭环**：先手工输入少量片段，完成音色配置、生成、保存、试听、重跑、最近通过版恢复、同源母版和导出，验证文件及任务恢复。
3. **原文提取与角色延续**：接入文本模型、区间覆盖检查、角色匹配和人工校对，验证同名、分块和跨章信息边界。
4. **整章体验**：完成批量队列、列表筛选、跟随滚动、整章检查、备份恢复；针对真实反馈处理音量或停顿问题。
5. **完成样章验收后确定发布方式**：本地版先可持续使用，在线版再落实身份、持久目录、资源和发布验证。

声音阶段交付物包括原文、确认剧本、各次实际生成输入、音频、人工问题记录、返工结果和合并成品。采用“通过／需返工／不可用”并记录原因，不凭少量样本虚构通过率。至少保留一段被用户认可的完整成品；若声音效果不满足目标，先修正参考、分段、提示或模型接入，再扩展功能。界面及普通数据工作可并行推进，不设与实际问题无关的额外审批。

开发前仍需落实：文本模型选择、后端语言、声音实际效果、供应商限流及计费边界、目标播放器兼容性。它们是待验证事项，不把审核对话中的外部验证声明当成本项目已执行证据。

## 17. 视频与模型能力补充：表演、声音创建和短段对戏

详见 [Seed Audio 1.0 能力补充与设计调整](./Seed-Audio-1.0能力补充与设计调整.md)，其中记录了视频观察位置、官方资料、设计取舍和最小验证组合。视频仅做分段画面与字幕核对，没有完整逐字转录或音频听辨；不得写为已复现其演示效果。

### 17.1 优先补入的产品设计

1. **完整表演指导**：在现有自由描述中支持情绪变化、身体状态、发声方式、停顿和声音动作。正文保持独立，不把表演说明当台词；AI 建议仍需用户采用。先用一个可编辑字段，不建设复杂参数面板。
2. **描述声音并保存到音色库**：在上传参考之外，允许用文字描述生成短样音；用户选中、命名并保存后作为参考资产复用。角色依旧从音色库选声音，不把描述本身当作固定音色，也不宣称永久训练。
3. **可选短段对戏实验**：用户选择连续台词作为一组生成，共同表达接话、打断和情绪递进。基础首版不依赖该实验完成；达到实际效果与成本要求后再开放正式功能。

前两项分别复用已有表演输入和音色资产流程；声音创建需在其复用一致性验证后交付。对戏组尚未纳入第 13 节基础验收，不能仅因写入设计就宣称已实现。

### 17.2 对戏模式与基础模式的明确差异

| 规则 | 逐条模式 | 对戏扩展 |
| --- | --- | --- |
| 生成与返工单位 | 单条 | 整组，按钮明确显示受影响台词 |
| 角色音色 | 每条绑定音色库资产 | 各角色仍绑定资产；组内参考数量受实际接口约束 |
| 播放覆盖 | 每条一个当前结果 | 每个组结果只覆盖一次其成员台词，不重复叠加单条文件 |
| 额外间隔 | 相邻片段间插入 | 只在独立生成单元之间插入，组内不再按行加静音 |
| 高亮 | 按真实片段时间高亮 | 没有对齐结果时只高亮组，不假装逐句精确 |
| 重跑后的续播 | 断点条开头 | 断点组开头；内部按句定位需真实映射 |
| 改一句后的影响 | 本条需更新 | 整组需更新；不能承诺混合音频无损局部替换 |
| 恢复精细控制 | 原生支持 | 用户解除分组，复用已有匹配单条或重新生成缺失条目 |

本章只读、任务恢复、安全替换、用户检查和最近通过版保留原则同样适用于组结果。先验证这种返工代价能否换来更好的表演，再决定推广范围。

### 17.3 不直接作产品承诺的能力

整段声音场景、时间控制、多语言、图片参考和长音频延展都有进一步探索价值，但本工具当前路由和交付规则需要分别验证。混合生成不等于独立轨道，提示时间不等于测量结果，接口能接收参考不等于音色与情绪可完全解耦。

因此保留默认干声与逐条制作；场景声音由用户主动选择并保留干声。原生续写、自动音频局部编辑、视频参考和分轨返回没有在本项目当前路径取得可用证据，不新增猜测参数。

“保留干声”指保留已有干声资产；没有干声时不隐式增加一轮生成。若用户需要两种版本，应显示各自生成范围并由用户发起。

### 17.4 专用写作规则

把用户提供的结构化提示框架整理成项目自己的写作规范：朗读内容、角色参考、情境、逐句表演、互动时序、可选声音事件、声学主次。普通片段仅使用必要维度，中文优先，不把标签当成官方强制语法，也不把时间要求当作实际时间戳。

完整正文和表演要求统一组合到实际 `text_prompt`；当前接口的 `instructions` 不能用作与正文自动合并的附加说明。首版复用现有编辑字段和生成记录，具体模板、示例与验证方法见 [专用剧本与提示词写作规范](./Seed-Audio-1.0专用剧本与提示词写作规范.md)。
