# 实施记录与必要调整

固定起点：`ae96c84cb2c7c6ae209e428010faa289a0b9e181`。总路线保持 M0 隐患修复 → M1/M2 并发 → M3 受控助手 → M4 有界托管 → M5 分项验收。

## 用户补充

- 助手初始模型为 `claude-sonnet-5-5`，只是可编辑默认值。配置保存在独立助手连接中，不以条件分支锁定特定模型。
- 独立多模态连接依据用户提供的《Kunpo多模态模型调用说明》使用兼容的 Chat Completions 消息与真实图片像素。没有依据接口名称推断视觉能力。
- 自动尾部清理仍是默认流程。原件留存在后台，恢复入口按需展开，未增加每次手动清理步骤。

## 实现采用既有机制

- 助手业务调用复用 `domain`、`analysis`、`experience`、`worker`；HTTP 与助手共用音频可用性检查。不提供任意 action、HTTP、文件路径、SQL 或 shell 工具。
- 委托下产生的安排记录 AI 来源；明确审批和人工听评分开。人工保护字段、原文范围和费用守卫仍在业务执行边界生效。
- 队列与关闭流程使用真实在途记录与 drain；同章任务锁保留。跨章和试音共用音频槽，本地整理与网络请求分开。
- 本地媒体处理另在共有进程入口限制为一个进程，覆盖上传、校验、截图解码和渲染，避免旁路入口超过处理上限。
- 没有新增依赖。完整音频的完整性记录用于文件系统与数据库不能同时提交的崩溃恢复；附件摘要用于确保预览、发送和迁移的是同一份像素。业务对象版本与去重继续使用版本号、主键、事务和稳定操作记录。

## 与总规格的澄清

1. 真实供应商并发上限未经验证时，实际运行保持 1。开发测试中的账号上限与模型响应均来自明确标识的模拟服务，不能作为账号能力证明。
2. 识图挑战使用随机 5×5 色格；答案只在像素中，符合“随机短码或特定形状”验证目的。文件名、文本提示和上下文不包含答案。
3. 工程测试、真实模型识图、音效听评、5 名新手与 2 名熟手研究、干净 Mac 安装分别记录。缺少其中一类证据时，不以其他类别代验，也不宣称全规格验收结束。
