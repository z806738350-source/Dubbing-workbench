## 实现要点

- 正文、角色身份、参考声音、表演指导分别保存。生成请求用说话者槽位，角色显示名不会替换原文中的人名。
- 首次绑定补齐本章未指定音色的片段；单条覆盖受保护。拆分继承实际配置，合并冲突需明确选择。批量改绑预览每条音色变化，有引用的角色不能归档。
- 分析草稿保存章节与项目上下文修订；用户勾选后一次应用。角色事实和别名只用于适用章节及其后续章节。替换原文先生成草稿，采用时原子更新并保留旧来源版本。
- 生成期间章节只读；进度登记不使同批后续请求过期。重复命令不重复入队。未知结果不自动再次付费，共享接口暂停跨重启保留。
- 音频先完整接收和解码，再登记结果。失败保留旧版；检查绑定音频及审核依据。恢复旧音频先看设置差异，不撤销当前角色归属。
- 音色库试音使用独立任务，不修改章节。参考删除先停止未来生成，等待在途任务及文件读取结束；已生成音频与成品保留。
- 播放会话在编排更新后失效；再次整章试听按稳定片段定位。旧音频试听显示当时正文。母版与导出使用相同音频顺序及帧级间隔，不在末尾附加空白。
- 备份和恢复拒绝覆盖已有目标；检查数据库及所有引用文件。服务只监听 127.0.0.1，拒绝不允许的跨站来源。

## 中文信息层次与视觉检查

采用 Hallmark，延续已确认的 Ardot 白灰面板、近黑主操作和克制绿色状态。Beautiful UI 与 React Bits 用作组织及反馈参考，未复制付费代码，未添加动画框架。

| 信息层级 | 呈现方式 |
|---|---|
| 当前朗读正文 | 16px、舒展行高、深色文本；选中行微调字重与底色 |
| 角色与实际音色 | 角色中等字重，音色使用次级对比度；与正文分行对齐 |
| 当前任务与关键操作 | 稳定位置、明确动作名称；主按钮用实色区分 |
| 状态、统计、来源与辅助说明 | 更轻对比度与紧凑字级，放在对应内容附近 |
| 分组与细节 | 留白、分隔线、背景层次组织，不靠大标题或装饰堆叠 |

按钮、选择器、输入、复选框、滑块、弹窗和播放器均使用定制样式。保留语义 HTML 的键盘与焦点行为；系统文件选取窗口由操作系统提供。

实际 Chrome 检查覆盖桌面 1512px，以及 320 / 375 / 414 / 768px。已观察到正文可读、主操作单行、无页面横向溢出；320px 额外检查批量改绑弹窗及自定义选择器。桌面采用紧凑控件密度，触屏主要交互目标不少于 44px。命名颜色的 WCAG 静态计算：正文/白底 17.31:1，辅助字/输入底 5.49:1，绿色状态/选中底 4.66:1，白字/绿色按钮 5.19:1，控件边界/输入底 3.19:1。该计算不等于全 DOM 扫描；没有宣称全部 Hallmark 规则已通过机器扫描。
