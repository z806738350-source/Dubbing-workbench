# Seed Audio 1.0 能力补充与设计调整

- 日期：2026-09-24
- 关联：[工具设计方案 v0.2](./配音工作台工具设计方案-v0.2.md)
- 写作落地：[Seed Audio 1.0 专用剧本与提示词写作规范](./Seed-Audio-1.0专用剧本与提示词写作规范.md)，将表演及场景能力转化为剧本整理指令和实际生成示例。
- 目的：检查原方案是否把模型能力限制得过窄，并提出可与逐条返工共存的扩展方案。
- 状态：资料核对及设计建议；未新增付费生成，没有模型效果验收结论。

## 2. 与原厂、接口资料交叉核对

本次成功读取了此前未能取得的 Kunpo 页面，并读取原厂文章与接口文档。

- **原厂定位**：支持声音场景编排、描述或参考样音塑造声音、丰富表演、多语言及后续延展；文中对人声时序给出 100 ms 粒度描述。多轨与更多输入模态仍在未来方向中。以上为原厂声明，不等于当前 Kunpo 路由都已实测。[Seed 官方介绍](https://seed.bytedance.com/en/blog/from-speech-to-audio-creation-introducing-the-seed-audio-1-0-audio-creation-model)
- **原厂 API**：自然语言可描述时长与说话区间；示例包含多名说话人和场景声音。图片与声音参考互斥，不能假定能把两种参考同时加入。[火山音频生成 HTTP](https://docs.volcengine.com/docs/DoubaoVoice/audio-generation-http?lang=zh)
- **当前接入**：Kunpo 定义纯文本、音频或图片参考；音频参考最多三条。当前客户端只拿音频二进制，不含字幕 JSON。不能由这些定义推导出混合音轨拆分、音频局部编辑或原生续写接口。[Kunpo Seed Audio](https://docs.ziy.cc/api-reference/seed-audio/)

结论：模型的创作范围确实比逐句朗读更广。已有设计为了保留单条编辑而选择了逐句流程，但没有充分呈现这些能力与适用场景；需要补充产品入口及明确取舍，不能把所有能力都归为不可用，也不能直接承诺全部稳定实现。

## 3. 优先补充：把“情绪”扩展为“表演指导”

这是对现有工作台最直接、成本最小的改进，保留单角色、单片段生成方式。

默认列表继续简洁展示一条表演摘要；右侧高级编辑可描述：

- 情绪和变化过程：平静转为疑惑、压抑着怒气、说到后半句哽咽。
- 发声方式：低声、耳语、喊话、带笑意、气息不稳。
- 身体与处境：边走边说、刚跑完、刻意不让隔壁听见。
- 节奏与重音：语速、某个词强调、句中犹豫、句末收住。
- 声音动作：叹息、短笑、抽泣、喘息等可作为生成意图，不保证每种动作稳定执行。

这些暂用一个可编辑的自然语言字段加少量示例，不先建设几十个互相冲突的参数。可以由 AI 根据原文提出建议，用户明确采用后写入；列表展示最终实际参与请求的指导。

正文与指导严格分开。不把“叹气”“哭腔”自动加成要朗读的文字；也不把模型增加的声音动作算作原文覆盖。用户仍能选择只读正文、不额外添加表演动作。

声音动作若已经写进该片段生成要求，应修改本片段重跑。两个人的抢话、重叠等不能仅通过给两条独立音频加描述来保证，需要第 5 节的对戏方案。

### 示例：本工具可以提供的编辑表达

正文：你终于来了。我还以为，你不会来了。

表演指导：前半句松了一口气，语气压低；后半句带一点委屈，在“以为”后短暂停顿。只朗读正文，不增加音乐或环境音。

此例是本次设计的提示词意图，不是已验证的固定语法或效果样本。

## 4. 音色库补充：文字描述生成候选声音

保留“上传参考音频”，增加可选的“描述声音”入口：

1. 用户描述年龄感、声线、口音和气质，不要求先找到外部参考素材。
2. 使用固定短样文生成候选声音；显示实际生成状态和费用提示。
3. 用户试听，选择保存、重新生成或放弃。
4. 用户命名并保存选中的候选音频，将它作为新的音色参考资产。
5. 角色仍然只能绑定音色库中的资产。

这条路径利用纯文本生成能力构建参考素材。后续请求复用用户选中的声音文件，不能只保存一段描述后每次重新凭文字猜音色，也不将它称为永久训练音色。

候选音频必须满足正式参考素材的规格；选用后保留来源提示词及原文件。测试“描述生成 → 保存参考 → 多句复用”是否保持身份，是该功能的验收重点。

暂不把参考图片放入首版创建入口。它可作为未来探索，但对小说文字工作流的价值低于描述声音，且需要另行验证图片指向的声音是否可复用。

## 5. 可选扩展：短段对戏生成

### 5.1 保留两种明确模式

| 模式 | 用户选择的单位 | 更适合的内容 | 返工单位 |
| --- | --- | --- | --- |
| 逐条配音（默认） | 一条片段 | 旁白、独立对白、强调可单条精修的章节 | 一条 |
| 短段对戏（实验） | 连续几条已确认台词 | 接话、打断、情绪递进、需要共享场景理解的对话 | 整组 |

首版基础闭环仍以逐条模式交付。短段对戏先做小样对比，效果和返工成本值得时再开放正式入口；在此之前属于设计规划，不显示为已可用功能。

### 5.2 用户操作与数据关系

选中连续台词 → 创建一个对戏组 → 查看本组角色、参考音色和整体表演指导 → 生成 → 整组试听与返工。

逻辑台词仍保留自己的原文、角色和指导。对戏组只增加“这些台词共用一次生成结果”的关系，不把原剧本重写成一个无法校对的大段文本。

按当前接口约束，初期实验只选择能用最多三条参考资产表达的组；旁白如使用独立参考也占一个位置。这是本工具实验范围，不声称模型最多只能理解三个角色。程序根据本组实际参考顺序生成音频编号，角色名本身不是供应商音色 ID。

整组提示及正文必须满足输入限制，预计时长留足余量。超限先让用户拆组，不用截断台词解决。将整段结果中的某句改字、换声或改表演后，整组标记待重新生成。

### 5.3 不回避逐句返工的冲突

一段混合音频里即使知道某句大概位置，也不能保证替换一句后，另一人的重叠声音、空间、停顿和情绪衔接完全不变。

因此，对戏组里的操作明确显示“重跑本组”，并列出受影响台词。不能仍用“单句重跑”的按钮让用户误解。需要逐句控制时，用户可解除分组，恢复已有的匹配单条音频，缺少的条目再分别生成；已保存的整组结果保留，不能隐式破坏已有选择。

一组新结果按 v0.2 的自动替换、待检查、最近通过版保留规则管理。章内某条实际播放来自单条还是组音频应当可见；编排中每句只能被覆盖一次，不能同时放入组音频和它包含的单条音频。

### 5.4 停顿、播放和高亮

- 0.5 秒设置只用于独立生成单元之间；组内的停顿、接话与重叠来自模型生成，不能在每行之间再次插入静音。
- 没有真实对齐结果时，整段播放只高亮对戏组，不按文字长度猜每句时间。
- 精确逐句定位需要真实时间映射：优先评估可获得时间戳的服务路径，或额外的音频对齐步骤；它们不自动包含在当前 Kunpo 接入中。
- 即使有转写时间戳，也需核对其是否准确关联原剧本，不能把漏读后的转写当作原文完整性证明。
- 断点以生成单元定位：组音频重跑后从组开头继续；不能在没有映射时承诺从内部指定句开头继续。

这些与逐条模式的原始体验不同，所以对戏必须由用户主动选择，不能自动把用户所有台词拼成组。

## 6. 其他能力如何安排

| 方向 | 设计处理 | 验证重点 |
| --- | --- | --- |
| 时间段、说话起点及总时长意图 | 对戏实验中允许高级自然语言指导；常规小说不要求用户逐句填秒数 | 实际起止误差、漏读、加速赶时长；提示值不是测量结果 |
| 音色参考与情绪参考 | 先记录参考素材的表演特征；独立指定“参考谁的声音、参考谁的情绪”作为实验 | 能否分离身份与表演，是否串音；不承诺可自由解耦 |
| 环境音、音乐和音效 | 默认干声；以后由用户明确选择场景版本，并保留干声结果 | 台词清晰度、声场连续性、混合后返工成本；不能承诺分轨返回 |
| 单独声音素材生成 | 可探索为独立素材，先生成试听和下载；不因此立即建设多轨编辑器 | 素材可用性、首尾、循环性和实际时长 |
| 图片参考 | 后续能力探索，不直接混入已绑定参考声音的请求 | 图片／音频参考互斥及声音身份延续 |
| 多语言与口音 | 先中文验收；其他语种单独按供应商模型与样本验证 | 发音、声线稳定及内容正确；口音要求不等于所有方言已支持 |
| 长内容延展 | 原厂方向值得跟踪，当前设计不增加未经明确验证的续写参数 | 当前路由如何调用，接缝和角色一致性；普通拼接不叫原生续写 |
| 声道位置、压缩、EQ | 作为后期处理方向；不把视频中的制作建议直接当作模型请求字段 | 若需要，应在应用后期处理并与试听母版共用配置 |

## 7. 最小验证组合

复用同一段自有或已获授权的小说样本，用实际调用验证。本文仅定义实验，不执行生成。

1. **声音创建**：文字生成一段候选，保存后复用在多句台词；对照原始候选判断身份是否漂移。
2. **单条表演**：相同音色和正文，比较简单情绪标签与具体表演指导；检查额外增词、动作是否符合意图、身份是否变化。
3. **参考干扰**：比较中性参考与强情绪参考的表现，记录参考音量；先控制变量，不把不同参考的差异全归因于提示词。
4. **逐条与对戏**：同样几句对话，分别逐条和整组生成；比较衔接、串音、抢话、准确性和返工次数。
5. **时间意图**：记录指定区间和实际输出区间，不将官方粒度描述写成本工具精度承诺。
6. **声音场景**：干声与带环境的版本分别保留，检查台词是否被遮盖、能否承受整组返工。

记录每次输入、实际模型、参考资产、音频、等待时间、返工原因和估算口径。人工检查正文、声音身份、表演和可编辑性；不以画面提示、文件可解码或某个单次精彩示例代替验收。

## 8. 本次设计结论

应当补进产品设计的是：更具体的表演指导、描述生成声音并入库的入口，以及可选短段对戏模式。

逐条生成仍是默认制作方式，因为它直接满足原需求中的单条替换与精确定位。场景式生成值得作为用户可选择的表达方式，但返工单位、停顿和高亮规则必须随之改变。无需现在就建设完整音频工作站，也不应让首版的简化成为永久屏蔽模型能力的理由。
