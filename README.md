# 配音工作台

基于 React、Node.js 内置 SQLite 和 FFmpeg 的本地有声书制作工具。业务设计见 `doc/配音工作台工具设计方案-v0.2.1.md`，开发与验证进度见 `doc/开发里程碑.md`。

仓库包含源码、设计文档与验收摘要。密钥、小说测试素材、逐句听评表、生成音频、运行数据及备份仅保存在本地；验收文档中的这些本地证据链接在 GitHub 上不可用。

声音创建、多人干声对戏及场景版本已接入工作台。操作和限制见 [增强阶段使用说明](doc/enhancement/release-notes.md)，交付记录见 [增强阶段状态](doc/enhancement/execution-status.md)，逐项证据见 [增强验收矩阵](doc/enhancement/acceptance-matrix.md)。对戏与场景保持实验标识；工程通过和声音听评分别记录。

## 启动

需要 Node.js 22.13 或更新版本，以及可执行的 FFmpeg / FFprobe。

```sh
npm install
npm run build
npm start
```

浏览器打开 http://127.0.0.1:4318 。开发模式运行 `npm run dev`，打开 http://127.0.0.1:5173 。服务仅监听本机。

在项目根目录的 `.env.kunpo` 配置 `KUNPO_API_KEY`、`KUNPO_BASE_URL`、`KUNPO_TTS_MODEL`。文本分析默认使用 `gemini-3.8-flash`，可以在“设置与连接”输入任意 Kunpo 支持的模型名称并保存。可选 `KUNPO_TEXT_MODEL` 作为初始默认值，界面已保存的选择优先。密钥不发送到前端、不写入日志，也不包含在数据备份中。不要分享该文件。

可用环境配置：`DATA_DIR` 指定独立数据目录，`PORT` 指定本地端口，`FFMPEG_PATH` / `FFPROBE_PATH` 指定处理程序。未指定时优先使用本机 `~/.local/bin/ffmpeg`。

有限音频实验可配置 `KUNPO_AUDIO_CALL_LIMIT`（正整数）和 `KUNPO_AUDIO_USAGE_SCOPE`（本轮名称）。额度在入队事务中预留，未发送释放，已发送失败及结果不明仍计入；同一范围不能改上限或清零。它控制本机提交次数，不能替代供应商账单。

文本分析不在工具端设置输出 token 上限，不发送 `max_tokens`，采用服务商自身的规则。实际调用按用量计费，超时或服务商返回截断结果时停止，不自动重复付费。

## 制作

逐步操作与常见问题见 [工具使用说明](doc/工具使用说明.md)。

1. 新建项目，导入 UTF-8 TXT / Markdown。预览原文后导入，Markdown 默认作为纯文本。
2. 手工校对片段，或使用“整理剧本”创建 AI 草稿。普通章节整章分析；较长章节按原文边界分批。有效草稿会保留，错误标注可本地校对，缺口可补齐；服务失败后可只继续未完成批次。结果不明的请求需明确确认可能重复计费才会重发。审阅后明确应用，角色待确认状态不会自动消失。导演建议可以多选后一次应用。
3. 添加不超过 30 秒、10 MB 的 WAV / MP3 参考，绑定角色或单条覆盖。音色库可主动生成新文本试音；归档、停用、删除参考文件均有独立状态。
4. 确认角色和声音身份，再生成所选片段或本章待办。真实模型调用按服务商规则计费。
5. 试听、检查，必要时单条返工。整章试听会先准备母版，准备好后再次点击播放，确认检查后导出 WAV / MP3。

“生成成功”只是技术结果，仍需人工检查台词、声音身份和表演。实际样章验收记录与剩余限制在开发里程碑文档中。

## 停止、备份与恢复

运行服务的终端按 Ctrl+C。服务停止后续派发并等待在途请求结束；强制退出后的结果不明请求不会自动重发。

服务完全退出后执行：

```sh
node scripts/backup.mjs create data /绝对路径/新的备份目录
node scripts/backup.mjs verify /绝对路径/备份目录
node scripts/backup.mjs restore /绝对路径/备份目录 /绝对路径/新的恢复目录
```

使用 `DATA_DIR=/绝对路径/新的恢复目录 npm start` 打开恢复数据。命令拒绝覆盖已有目录，原数据保留。备份包括正文、角色、参考、任务、音频与导出文件，不包含根目录密钥文件。

停服后可显式清理无引用文件，先预览，再执行：

```sh
node scripts/backup.mjs cleanup data
node scripts/backup.mjs cleanup data --apply
```

只清理四个素材目录中程序命名且没有记录引用的 WAV/MP3；保留全部历史记录、旧导出、备份、未知尝试产物及临时文件，不自动回收历史版本。有未结束任务、缺失引用文件或服务仍在运行时拒绝清理。操作不可撤销，建议先按上面的命令备份。

## 检查

```sh
npm test
npm run build
```

测试使用临时数据库与测试合成音频，不访问付费模型。`scripts/live-smoke.mjs` 是单独的付费真实接口检查脚本，不属于自动测试；只有获得明确授权后才运行。
